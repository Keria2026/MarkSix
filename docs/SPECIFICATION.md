# MarkSix V1.0 业务与开发规范

本文件整合已确认的需求及部署测试反馈，是当前实现依据。旧版本文档不再混入当前说明，历史内容可在 Git 中查看。系统由多个相互隔离的盘口方账号使用，每个盘口方自行手工录注，不提供投注人自助下注或支付功能。托管授权和部署规则见 [架构](ARCHITECTURE.md)。

## 期次、时间与开奖

- 使用北京时间。期号 `YYYYDDD`，每天一期，00:00 切换；元旦重置 `YYYY001`，闰年允许第 366 期。
- 默认接受投注区间 `[08:00,21:28)`，以服务器收到请求的时间为准。
- 开始和封盘时间可配置，开始须早于封盘且不跨日。提交时间表后弹出身份认证，不在配置页常驻账号密码输入框；认证通过才保存，下一期生效，已形成的当前期不重新开放。
- 封盘前允许录入、纠正金额、飞出及撤销；封盘后禁止新增操作。已成功请求的幂等重放只返回原结果，不产生新操作。
- 默认 21:34 开始，每 60 秒抓取 `https://macaumarksix.com/api/macaujc2.com`。获取本期有效结果即停止；先收到更晚有效期次或到达下一期 21:34 时停止旧期抓取，标记开奖缺失，保留投注。
- 核验期号、日期、7 个不重复的 1–49 号码、生肖和波色字段。异常结果不结算；冲突结果保留首次接受的结果并提示。结算和所有账目更新在同一事务中，重启可恢复。
- 开奖球的红／蓝／绿颜色直接使用接口返回波色。已开奖生肖和波色以接口为结算依据；与预测映射不符时明确提示。

## 玩法及选择规则

一个玩法只有一种投注对象：号码、生肖、波色、尾数、单双、大小或生肖种数。范围为平码前 6 球、特码最后 1 球、全部 7 球。波色当前只支持特码。

命中条件：全部命中、全部不命中、至少命中一个、至少命中 N 个、特碰、软碰。重复出现同一生肖／尾数只算一个选项命中。不同选项不能重复选择。

| 配置 / 操作 | 拆注方式 |
| --- | --- |
| 所有新玩法 | 手工新建默认关闭复式；默认包与导入按文件开关，配置启用后录入页才出现复式选项 |
| 每注 1 项的普通多选，如特码选 06、45 | 2 条独立基础注，每条 1 个号码 |
| 未启用复式，等于 5，选 7 肖 | 拒绝；必须选 5 肖 |
| 未启用复式，不少于 5，选 7 肖 | C(7,5)=21 条，每注 5 肖 |
| 未启用复式，不多于 5，选 4 肖 | 一条 4 肖基础注 |
| 已启用复式，用户选择复式，候选 n、拆分 k | 生成 C(n,k) 个不同组合；k 必须满足数量关系 |

录入支持点击选项及文本输入。文本以空白、中英文标点或符号分隔，接受全角数字，重复项只计一次；无法识别或超过规则边界时整次输入不应用，并禁止提交。特碰保留输入顺序。文本与按钮选择同步，仍由后端完整校验。

普通模式的拆分数量由数量阈值决定；复式拆分数量仅用于复式模式。候选数超过单次容量时明确拒绝，不能截断组合。

**二中二：** 不含特选择号码、平码、全部命中、等于 2；表中普通赔率 60 倍。含特另建玩法：号码、全部、全部命中、等于 2，普通赔率 55 倍，启用 `special_hit_odds=25`。两平码中奖按 55 倍，一特一平按 25 倍，逐基础注判定；不能用本命肖特殊赔率代替这个规则。同时启用本命费率时，中奖含特码基础注优先使用含特码赔率，反水仍按原本命规则。

**生肖种数（四肖亮等）：** `kind=zodiac_count`、目标 `zodiac_count` 为 1–7，固定全部范围、全部命中、等于 1 项、每注 1 项、关闭复式及本命费率。所投选项为配置的目标种数，不选择具体生肖；全部 7 球的不同生肖数恰好等于目标即中奖。以开奖接口生肖为准，重复生肖只计一种，49 不退本。

**三中二：** 配置号码、数量等于 3、至少命中 2 个，并选择开奖范围。选出的 3 个数至少 2 个在范围内出现即中注，3 个都中也中奖；它是一条基础注，不自动拆成 3 个二数组合。

**特碰：** 号码、全部范围、等于 2、关闭复式。依次选 06、45：06 必须是特码，45 必须在平码。顺序保存在快照中。

**软碰：** 同样选 2 个号码，一个是特码、另一个在平码，允许互换；两个都只在平码中不算中奖。

**大小与单双：** 小为 1–24，大为 25–48。所选范围含 49 时，该玩法全部基础注和局：本金全退、无反水、有效本金和有效基础注均为 0。只在大小／单双玩法中退本；号码、生肖、尾数等仍正常结算。已保存的基础注保持提交时的快照语义。

## 年度生肖与特殊费率

固定顺序：鼠、牛、虎、兔、龙、蛇、马、羊、猴、鸡、狗、猪。2026 本命马，2027 羊，2028 猴。01 为本命肖，号码每加 1，生肖沿固定顺序向前退一位；12 个号码循环一次。01、13、25、37、49 均为本命肖。

每年 1 月 1 日当期自动采用新映射。每期映射不可变；管理员可为未来日期安排校正映射，同一年内生效，下一年重新自动轮换。预测和展示使用本期快照，实际开奖使用接口数据。

号码、生肖、尾数、大小、单双可分别启用本命肖特殊赔率及特殊反水。逐条基础注判断：号码包含本命号码、生肖包含本命肖、尾数等选项包含本命号码对应特征时适用；不含本命选项的其他基础注使用普通费率。“全部不命中”玩法也使用同一判断。配置变动不追溯历史投注。

## 金额、投注人及账目

- 投注人手工填写，去除首尾空格后 1–80 字符，不含控制字符。相同名称汇总，区分大小写；旧记录为空并单独显示。
- 原投注每条基础注金额为正整数元。赔率最多 4 位小数，反水百分比最多 2 位小数。
- 所有金额使用整数分，赔率使用缩放整数；乘法使用 i128。每基础注分别四舍五入到分，再汇总，无浮点金额运算。
- 中奖含本返还 = 每注本金 × 适用赔率；反水 = 有效本金 × 适用比例，无论输赢均计算，和局除外。
- 纠正金额：只改变同一原记录的每注金额，不改变投注人、选项或规则快照；记录前后金额、版本和时间。不得低于该条已飞出的每注总额。
- 飞出：原受注记录保持不变；手工选择／填写受注方，按每条基础注相同金额飞出。最少 0.01 元，可部分或全部飞出给多个受注方，累计不得超过原每注金额。
- 飞出沿用原基础注赔率、反水和特殊费率快照，独立逐注舍入。飞出方本身是这部分账目的投注方。
- 原投注有关联有效飞出时，先撤销飞出，再作废原注，避免孤立账目。撤销记录保留至客户主动清空该历史期，不参与有效统计。
- 修改和飞出使用请求 UUID 幂等及记录版本校验；并发写入按期次行锁串行检查，避免重复飞出或覆盖修改。

以非和局有效本金 S、含本返还 P、反水 R 计算：

| 口径 | 净盈亏 |
| --- | --- |
| 投注人 | P + R − S |
| 本方原受注 | S − P − R |
| 本方飞出 | 飞出 P + 飞出 R − 飞出 S |
| 飞出受注方 | 与本方飞出净盈亏相反 |
| 本方自留 | 原受注净盈亏 + 飞出净盈亏 |

和局退回本金单列，不计入有效本金及中奖返还汇总，但保留在基础注原始结算结果中。未结算／开奖缺失记录不显示已实现盈亏。自留采用原受注与飞出实际舍入后的金额相减，不重新对净额舍入。

例：原受注 150 元，赔率 2、反水 2%，其中飞出 40 元。中奖后原受注净额 −153 元、飞出净额 +40.80 元、自留 −112.20 元。

## 组合单与投注人对账

组合单属于同一期、同一投注人，包含 1–100 个独立分项，合计不超过 1,000 条基础注。它是收据分组，不连乘赔率。各分项独立保存规则、费率与基础注快照，逐注计算后相加；普通单笔仍可直接提交。任何分项不合法、规则版本过期、超出容量或收到请求时已封盘，整单不保存；同一提交编号重试不会重复入账。

封盘前可修改、撤销分项，也可整单撤销。飞出始终指向具体分项；有未撤销飞出时，整单撤销被拒绝。整单撤销校验全部分项版本后原子执行，保留原记录和审计。列表按单展示，金额筛选和排序采用未撤销分项的本金总额，玩法筛选命中任一分项即显示完整单据，不在分页中拆开组合单。统计、容量及风险仍按底层分项／基础注计算，界面明确区分单据与分项。

投注人分类统计支持导出当前查看期数的全部投注人，一人一份 A4 PDF，打包 ZIP。使用投注人视角，展示总净输赢、反水（水钱）、组合单及每条基础注的判定、返还、反水和净额；撤销项标记作废并排除汇总，和局退本单列，未结算输赢显示待结算、反水标记预计。飞出不影响原投注人的账目。导出在同一账本版本读取，生成期间的新投注不混入；切换期次、退出或取消导出会终止生成。

文件名采用投注人代号；非法文件名字符替换，Windows 保留名称加安全前缀，大小写冲突加序号，过长名称按文件系统限制缩短。每次导出上限为 1,000 位投注人、10,000 个分项及 50,000 条基础注，包含撤销记录；超限明确拒绝，不截断、不漏人。

## 风险与容量

投注页展示投注者最大返还及最大净盈利；盘口页面展示原受注有效本金、预计反水及计入飞出后的自留最大可能净盈利／亏损，分别附达到该值的合法开奖示例。

极值必须来自同一个由 7 个不同号码组成的合法开奖结果，不能把各条最大值简单相加。采用精确搜索；根据本期快照和投注版本计算，金额修改、飞出、撤销及录入均使旧结果过期。超时／失败显示状态，不显示估算值或冒充当前的旧结果。

每个客户每期最多 1,000 个未撤销投注分项、10,000 条有效基础注；每次提交合计最多 1,000 条基础注。组合单的每个分项分别占用记录容量，不能通过合单绕过限制。飞出独立限制为每期 1,000 条有效记录和 10,000 条基础注。撤销不占有效容量，随历史记录保留至客户主动清空。

计算预算 60 秒（包含排队），允许后台计算时继续录入。托管版共享精确计算并发上限，超时不会返回估算结果。2 vCPU／1 GB Ubuntu 是性能验收目标；固定基准不能证明所有任意玩法配置均能在一分钟内完成，实际验证范围见 TESTING.md。

## 页面与交付

- 导航：本期概览、录入投注、本期统计、历史统计、玩法与配置、官方频道。
- 二级菜单控件与所属一级项同行，子项缩进；窄屏以再次点击当前一级项展开／收起。第一次默认收起，后续保留用户的显式选择。已打开的历史详情先点击历史入口返回总览，再点击可切换菜单状态。
- 弹窗使用统一入场动效，并遵守减少动态效果偏好。弹窗打开时背景不可操作或滚动，内部仍可滚动；最后一个弹窗关闭后恢复原页面位置。
- 本期统计二级项：全部受注、飞出受注、投注人分类、投注记录；概览可看投注人汇总。
- 历史详情始终保持历史导航，并大字显示期号，可切换投注人及受注方汇总。
- 投注记录支持已有玩法、投注人复选框筛选、整单未撤销本金上下限及升降序；筛选组间取交集、组内取并集，空选表示全部。分页覆盖当期全部记录，自动刷新当前筛选，详情含拆注、关联飞出及操作记录。
- Liquid Glass 界面保留文字对比、清晰标签、键盘焦点、移动适配及减少动态／透明度偏好。
- 官方频道内嵌 `https://macaujc.com/picker/`。该网页本地筛选，不存在已确认的独立挑码 API；其生肖历法是外部网站口径，不写入本系统映射。若官网禁止内嵌或无法联网，可新窗口打开。
- 开发推送 dev，验收后由运营方合并 master，Actions 验证后自动部署 VPS。Docker Compose 运行四个服务，Nginx 按两个域名转发。客户免安装。所有文档随版本同步。

## 配置共享与托管授权

- 玩法可导出全部或单条 JSON，导入先预览，整批校验后同名覆盖当前规则并递增版本，不同名新增。文件内重名拒绝；若现有配置存在多个同名，整批拒绝，先整理重名项。文件只包含 rule 和 enabled，不含账号、投注、设备或授权；schema=1，最多 1,000 条且活动配置总数不超过 1,000。删除玩法使用版本校验和逻辑删除，保留所有历史引用。
- 玩法顺序可在配置中置顶、上移和下移，保存到客户账本，录入列表、搜索结果及导出数组沿用该顺序。排序不改变规则版本；同名导入保留本地顺序，新玩法追加末尾。
- 玩法卡片右上角选择控件与编辑入口分离。批量可修改除名称外的规则字段及启停状态，包括数量、复式和特殊费率；留空保持原值，可选限制／特殊费率支持显式清除。按各玩法合并后的规则完整校验，任一失败整批回滚；版本冲突必须重新选择，历史快照不变。
- 投注页支持名称包含匹配、唯一或同名精确命中自动选中。规则的 `selection_limit` 可选，用来限制候选总数；严格等于／不多于的非单选普通玩法仍不能超过阈值。越界点击和模式切换提示并阻止，不自动截断，不静默换掉已选项；后端重复完整校验。
- 托管版账号、一次性激活码、单会话、截止日及永久删除以 [账号授权](LICENSING.md) 为准。客户之间使用独立业务数据库与数据库权限。
- 托管版全新开始，旧系统及备份独立保留。发布前冷备份控制库与各客户账本，迁移失败不把旧程序直接连接到新库。恢复使旧会话失效，保留当前删除凭据。
- 当前仅交付 Ubuntu VPS Docker 托管版；Windows 用户使用浏览器，不再交付本机安装包或设备授权服务。

## 0 尾特殊赔率

尾数 0 只有 10、20、30、40 四个号码，其他尾数各五个。每个尾数玩法可独立启用并填写 0 尾含本赔率（最多四位小数，大于 0），其他投注对象禁止设置。按拆分后的基础注判断，包含 0 尾则使用该值；若同时符合本命肖赔率，0 尾优先。普通赔率、本命肖赔率和 0 尾赔率不相乘。反水保持原规则，未启用时保持原有结算。全部不命中等条件同样适用该逐注判断。规则和基础注均保存提交时快照。

## 客户主动清空历史

入口为玩法与配置。客户必须输入当前登录密码及“永久清空历史记录”，页面突出提示不可恢复。只删除当前账号本期业务日期之前的全部期次、投注（含撤销）、飞出、结算及对应金额变更／审计，不接收客户 ID 或任意数据库名。保留本期、规则配置、映射配置、账号、授权和会话。过期但未停用客户仍可通过有效会话调用清空接口。

删除服务器管理的本账号托管备份，保留其他客户独立备份及非实名清空凭据；清空前的全量备份不得恢复，需要重新生成完整备份。服务器外独立保管的副本不由网站控制。操作使用幂等 UUID、账号和期次行锁、统一备份文件锁，防止并发结算或备份带回已清空数据。

## 运行日志

Rust 服务固定仅记录 error，环境变量不能开启 info/debug。Nginx 仅记录 error 并关闭 access_log；MySQL 关闭 general/slow/binlog 并设置最低错误详细度。Docker json-file 限制为每服务 3 × 10 MB。数据库中的金额及授权审计用于业务追溯，独立于运行日志；清空历史仅清除对应历史期的财务审计。

## 风险任务状态

待计算、计算中、完成、过期、超时和失败分别展示。每次执行有独立任务 ID，并绑定投注版本；只有 ID、版本及待开奖状态均匹配时才能提交结果。结果保存最多尝试三次；失去执行者的任务或运行超过 75 秒的任务进入失败状态。正常求解预算仍为从请求入队起 60 秒，75 秒是故障回收上限，不是新的计算时限。进程重启重新排队，不复用未完成结果。失败／超时可手动重新计算；重复点击不能重启正在执行的任务。

退出、会话失效或授权失效必须销毁客户工作台及业务弹窗，取消请求并拒绝迟到响应。再次登录／续期后建立新的工作台状态；按账号保存的纯导航偏好可以保留。
