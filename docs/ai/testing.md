# 测试边界

## 分层

| 层级           | 位置                                   | 验证边界                                 |
| -------------- | -------------------------------------- | ---------------------------------------- |
| Rust 纯规则    | `backend/tests/rules.rs`               | 金额、规则、展开、结算、时间和默认配置   |
| Rust 内部契约  | 模块内 `cfg(test)`                     | 私有认证、风险求解与任务恢复             |
| MySQL 事务     | `backend/tests/ledger.rs`、hosted 测试 | 原子性、重试、快照、隔离与生命周期       |
| 生产入口       | `backend/tests/process.rs`             | 双服务启动、内部转发、健康检查与优雅退出 |
| 浏览器无关逻辑 | `frontend/tests/unit/`                 | 解析、编译、请求作用域与提交恢复         |
| 浏览器系统流程 | `frontend/tests/e2e/`                  | 登录、录入确认、模块、刷新与可访问性     |
| 运维           | `scripts/tests/`                       | 配置、备份、发布顺序、工件验证及失败边界 |
| 容器系统检查   | `scripts/verify_hosted.py`             | 两端路由、TLS 和真实运行镜像             |

测试层级参考微软 [Unit vs Integration vs System vs E2E Testing](https://microsoft.github.io/code-with-engineering-playbook/automated-testing/e2e-testing/testing-comparison/)。纯规则尽量脱离浏览器；需要 SQL 事务的断言使用真实 MySQL；浏览器只承担页面和系统连接行为。

## 隔离

`TEST_DATABASE_URL` 必须指向独立实例的 `marksix_test`。测试库中的数据可重置，不能共享开发服务正在使用的库。租户开通测试使用同一测试实例的 provision 身份，租户名由测试控制库的账号生成。

测试 API 使用固定业务时钟和新初始化的默认玩法，不复制生产默认配置文件。浏览器进程串行运行，避免单会话账号互相踢出。测试服务器不编入生产镜像。

## 金融与安全断言

期望金额由测试中的固定输入和独立算式给出，不通过被测计划函数计算期望。规则覆盖有效值与拒绝边界；结算覆盖命中、不中、和局、特殊赔率与反水。

事务测试检查失败后的数据库状态、重复请求后的记录数量、规则变更后的历史快照及结算重复执行。会话测试检查两客户互不可见、旧会话失效和到期拒绝写入。

提交故障注入分别模拟到达数据库前失败与提交后响应丢失。恢复测试检查持久化标识、账号隔离以及原文不进入本地回执存储。

## 执行入口

常用命令见[本地开发](../human/development.md)。完整顺序由 `.github/workflows/ci.yml` 维护，包括依赖审计、静态检查、数据库测试、语料生成评估、浏览器与镜像检查。

合成语料生成器默认生成 30,000 条带独立语义标签的记录，按 70% / 15% / 15% 分为训练、验证和测试集。生成时检查全局唯一标识、NFKC 与空白归一化后的文本、语义指纹，以及渲染模板跨集合隔离。已接受语义的选号次序、金额等价拼写和排版变化不能增加样本数；拒绝样本以归一化原文区分。单元测试重新生成整批语料并比较 SHA-256，CI 分别校验三个集合的精确语义、基础注数量、整数分本金和原文范围。

合成语料与测试结果位于忽略的 `test-results/`，CI 的 `text-entry-corpus` 工件包含语料、清单和评估报告。生成候选词典后检查 Git 差异，确保生成物可重复。

覆盖率的采集入口、分母口径、未测文件与严格目标检查见[质量验证与迭代入口](quality.md)。
