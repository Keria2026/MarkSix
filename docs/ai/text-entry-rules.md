# 文本录注规则与边界

本文按业务意图归纳当前识别规则，并说明遇到边界时应接受、要求修正还是交给服务端拒绝。实现流程与原文映射见[文本录注](text-entry.md)，测试边界见[质量验证](quality.md)。

## 处理链与判定依据

浏览器执行有限归一化、词法匹配、上下文组装和分项编译；服务端预览及提交使用当前账户的玩法版本和当期期次重新校验。规则识别不能决定实际投注期次，不能绕过服务端金额、基础注及事务限制。

识别成功要求玩法、市场、对象、组合方式、单价和合计全部一致。仅返回若干有效行或总金额碰巧相同不算成功。未知正文、冲突说明和不完整分项须显示为可修正内容，不能当成无意义文字删除。

## 规则清单

| 类别                   | 当前解释                                                                                                                                 | 必须保留的边界                                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 文字与字形             | 词法阶段支持 NFKC；全角数字、有限繁简字形、财务大写数字及猴的已知异体字归一，保留原文区间                                                | 精确配置的玩法及有效个人简称先保留原名，不能归一成另一套规则或费率；任意错别字不直接删除                                                 |
| 拼音与同音             | 支持有限拼音词表、组合拼音数词、唯一可判断的同音候选                                                                                     | 多个候选不按词频擅选；省位金额及不完整拼音须修正                                                                                         |
| 玩法来源               | 使用当前账户启用的玩法、版本有效的已确认简称、领域别名和离线候选词典；精确名称优先                                                       | 已禁用、已删除及版本过期的习惯不参与选择；多个同名配置仍需明确选择                                                                       |
| 玩法别名               | 特／T 为特码，平依对象语义处理；有／友／连／连肖及数字数量写法对应连肖；连尾／尾连、二中二带特／含特对应各自规则                         | 不凭别名创造未启用的玩法；有数量的连尾不能拆成生肖玩法；具体范围、数量关系和费率以配置为准                                               |
| 隐含玩法               | 无明确或继承玩法的裸号码默认特码；裸生肖配合逐号金额标记可默认特码；尾、波色、大小、单双在配置唯一且上下文兼容时推断                     | 头、尾、肖本身是选号方式；已有兼容玩法继续沿用。无计价证据的裸生肖金额保留逐号／包肖歧义                                                 |
| 市场                   | 新澳门默认；香港／港／香等显性标记优先；市场可在字段间或独立标题出现，后续继承最近明确市场                                               | 同项同时指定港澳须修正；标记不能倒灌到上一条或下一条。按对应市场映射展开生肖，提交实际期次由服务端确定                                   |
| 期号与昵称             | 行首数字期号、带“第”的期号作为元数据忽略；开头独立的非业务昵称或昵称冒号可保留在原文而不选号                                             | 正文中的期号样式不随意删除；以数字或金额开头的待定行不能当昵称吞掉；昵称不能隐藏玩法、金额或未知财务要求                                 |
| 号码                   | 01—49；明确分隔的单号、中文整数、合法的两位连写可识别；多余前导零可去除                                                                  | 0、50以上的选号、奇数位连写及未知字符须修正；单号重复保留为重复基础注，组合注内部重复不合法                                              |
| 头／尾／生肖选号       | 号码玩法中，0头为01—09，1—4头为对应十位号码；尾按个位展开；肖按市场当期映射展开。多尾可共用末尾“尾”                                      | 5—9头不合法；生肖和尾数玩法使用本类对象，不展开成号码。普通单项的重叠展开保留次数，拖池不能重叠                                          |
| 波色、大小、单双、肖量 | 使用当前配置的对象及数量关系；肖量玩法可按规则中的肖量补齐对象                                                                           | 没有相应启用配置时不自动建立玩法；不能把不兼容对象转成另一类投注                                                                         |
| 分隔符                 | 空白、点、顿号、逗号及横线可分隔选号；横线不表示范围或负数。重复斜线、独立 ll／ii 可分隔记录；x、星号和单斜线按上下文处理                | x／星号／斜线也可能表示单价，有明确后续单价或玩法证据才按选号分隔；未知字母单词不删除；金额中的负号仍不合法                              |
| 完整分组               | 括号组、逗号／斜线组、空白分隔的点号组、完整换行组可共享末尾玩法和单价；连肖可按已知数量识别完整生肖组                                   | 平铺号码不能按固定数量猜分；任何不完整组、嵌套／未闭合／空括号或组外残余须修正；重复完整组仍是重复投注                                   |
| 复式                   | 复式／复试／复氏／富士／付／复为复式标记；支持前后置及多数量连肖、连尾共用候选；相邻后置号码玩法可共用已声明的复式池                     | 必须启用复式并满足组合数量；未声明复式的多余候选不擅自组合。纯号码池超过数量且明确写“金额一组”时按限定语法判断复式                       |
| 拖                     | 明确左右候选，支持号码、尾和肖展开；全部生肖的号码拖可保留生肖拖语义                                                                     | 两边须合法、不同且无重叠，玩法须支持对应组合；缺边、多个拖标记及包肖金额与拖并用须修正                                                   |
| 单价金额               | 各、个数、各买、每注、每组等金额标记、前后置单价、中文整数及十百千万倍数；元／米／斤／块为金额单位；一组及一个数／一甲数可作受限定的后缀 | 正数、最多一位小数，尾随零可归一但不四舍五入；上限按整数分校验。省位金额、超精度、科学计数及无明确语法的千分位不猜测                     |
| 金额纠错与简写         | 共同金额标记后、带货币单位的尾字母O可按0纠正；完整选号组后重复斜线的大于49金额可作单价；完整的“号码.大数金额”对可拆分                    | O不在任意正文中替换；若后文另有明确单价，先保留选号校验；合法小数不拆成另一笔投注；小额或无证据的大数位置不随意猜单价                    |
| 包肖与总额             | 各肖／每肖／包肖及受限定的后置“一肖”表示每肖包号金额；共／合计可表示本项总额，精确分摊到角                                               | 包肖限单号码玩法与生肖对象；包肖与总额冲突须修正；普通逐号金额与每肖包号金额不能混同；下一条一肖玩法不能当上一条后缀吞掉                 |
| 上下文继承             | 同玩法续项可继承玩法和复式；新的显式玩法结束继承。显式连肖续项可按限定语法复用上一复式池                                                 | 不继承未知正文为候选；生肖投注后的独立纯号码行可回到默认特码；跨行、跨分号的后缀不能吞掉下一项                                           |
| 口语说明               | 有限礼貌连接词可消除；重复价格须一致；计价解释仅在与前一明确计价标记一致时作为冗余说明消除                                               | 更正、撤销、历史或未来引用（如上期、同上、昨晚、明天、下期）、冲突单价或逐号／包肖冲突均须确认；“不是总共”等财务说明不能当普通语气词删掉 |
| 合计                   | 组数／注数、金额、分玩法小计；行首合计校验整单，同行合计校验本段，独立后续合计校验此前全单                                               | 合计不生成投注；任一单价、注数、分玩法小计或总额冲突均阻止确认。编辑或排除行后必须重新核对                                               |
| 确认与学习             | 编辑结构化分项后调用服务端预览；成功提交后才保存简称与计价习惯；待提交标识支持响应丢失后的恢复                                           | 不从失败识别或预览写账，不跨账户共享习惯，不因刷新重复入账；陈旧预览不能用于新草稿                                                       |
| 资源与整单限制         | 原文最多12,000字符，解析行及提交分项最多100；编译限制单行基础注，服务端再限制整单最多1,000基础注                                         | 不自动截断原文或拆单；前端编译通过不等于整单可提交，服务端预览必须有效                                                                   |

## 词汇范围

玩法名称由账户配置决定，下面是固定领域词法；离线候选词典只提供候选，不保证词条唯一，也不替代启用状态检查。

- 特码：特码、特、澳特、T／t；平码：平码、平。裸“平”会根据生肖或尾对象进一步限定。
- 连肖：二—五或2—5，搭配有、友、连、连肖；一肖中还支持一有、1有、平特、平特一肖、平特肖、平特+肖、一肖、肖中。
- 连尾：二—九或2—9，搭配连尾、尾连；词法可识别不代表已有相应启用玩法。
- 含特及特殊别名：二中特、二中二带特／帶特、限定语法中的二中二韩特／韓特；四肖、新澳门四肖仅作为相应配置的候选。
- 观察词：三全中、特肖、特生、单肖、连生、串肖、正码、单平、尾数、色波等保留为领域候选；是否选中仍取决于规则、简称和同音候选的唯一性。
- 金额标记：各、个／個、各号、各注、每注、各组、每组、每尾、一组／1组、各肖、每肖、各数、共、总、合计、下，以及x／X、×、星号、美元符号和斜线。个／各／每及相应复数字样可搭配数字、号码、数、肖、组；支持已定义的繁体拼写，各打／各买按逐项计价。
- 组合词：复式、复试、复氏、富士、付、复；包肖、包；拖。单个生肖后的“中”可指一肖中。
- 拼音：已知市场、玩法词、十二生肖、拖／尾／肖、各／each／each group，以及ling至jiu、shi／bai／qian／wan等组合数词。未知拉丁单词不作为分隔符删除。
- 连接与说明：六合相关标题、帮我打、再来、另、买、压、来等有限连接词；其他口语归一化必须满足既定字段证据。表述金额、计价方式或撤销意图的文字不属于可自由忽略的连接词。

精确词表位于`vocabulary.ts`、`amount.ts`、`language.ts`及生成的候选词典；词法优先级、唯一候选判定和源码约束见`lexer.ts`。金额词表由归一化和词法阶段共用，避免同一个别名在两个阶段有不同解释。

## 从规则反推测试

按“业务意图→字段语义→文本排版”的顺序建立标签，使用独立整数分模型枚举基础注。分别统计正确接受、正确阻断、误拒绝、错误接受和语义不一致，并核对原文覆盖；不能用解析后的对象反推期望值。

`frontend/tests/model/text-rule-boundaries.ts` 生成规则交叉矩阵：选号与分组、复式与拖、前后置金额、全角及繁体、金额别名与OCR、港澳映射及继承、分段和整单合计，以及冲突说明、未知正文、非法金额与不完整组选项。个人玩法精确名称、版本与习惯失效另用契约测试核对。

```sh
# 仓库根目录；完整语料和失败记录保存在忽略目录。
bun scripts/check_text_entry_campaign.ts --suite rules --seed 20261107 --size 10000 --max-failures 10000 --output test-results/rule-audit --cases test-results/rule-audit/cases.jsonl

# 原有随机业务场景仍独立运行，避免只覆盖新增边界模板。
bun scripts/check_text_entry_campaign.ts --seed 20261108 --size 10000
```

这是一组有限的合成测试，不能换算成真实客户文本的识别率。真实98%目标需要独立、人工确认语义的留出集；歧义文本应作为确认场景评估，不能通过猜测提高识别率。

中文小数口语、省位金额、未确认的新玩法及带编号的混合抄单等仍需单独标注语义，不能仅凭标点推断。新增能力必须同时增加正确输入、矛盾说明和相邻字段反例，验证不会吞字段或改变计价方式。
