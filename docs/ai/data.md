# 数据与一致性

## 数据归属

控制库拥有 `hosted_accounts`、`hosted_workspaces`、`hosted_sessions`、`hosted_codes`、`authority_administrators`、`authority_sessions`、`authority_audit`、`hosted_deletions`。私有及协作数据库各自拥有业务管理员、会话、玩法及版本、映射、期次、投注单、投注、飞出、修改回执、偏好与审计。

运营服务拥有开通客户数据库与数据库用户的能力。客户服务使用受限控制库身份，再通过验证后的账号租用独立客户连接池。每个客户库由独立 MySQL 用户访问。

浏览器中的“投注人”不产生平台账号，也不能选择其他客户数据库。导出、搜索、回执查询和偏好查询均位于当前客户上下文。

管理员关联两个未关联且可用的账户后，新建协作数据库和独立数据库用户，不复制双方旧账。双方当前个人玩法分别复制到各自归属，不合并同名或相同设置。`plays.owner_account_id` 由会话确定，查看、维护、排序、导入导出、预览和提交均校验归属；切换记录范围不改变玩法归属。简称及投注人费率偏好以账户为联合主键，不能跨账户覆盖或匹配。已有关联账本升级时，由运营端从各自关联前的私有账本幂等初始化个人配置；旧共有玩法保留供历史快照引用，不再用于新录入。个人配置完成初始化后不会在重启时覆盖。初始化失败保留旧账与关联状态，可重试；失败账本不能接收投注。关联更新等待在途业务请求释放账户行锁，并使双方旧会话失效。请求只能选择 shared、mine、history 三个范围，不能传入账户或数据库标识。

`bets.created_by` 由已验证会话写入，不接受客户端指定，纠正、撤销不改变原始归属。mine 范围的筛选在服务端应用于概览、统计、记录、筛选选项和导出；容量及金额上限始终核对整个共享账本。协作中的提交摘要包含录入账户，避免两个账户复用同一标识时误归属。关联前账本拒绝业务修改与新录入，已有投注继续结算。

## 业务对象关系

- 玩法保存当前规则；玩法版本保存历次配置。
- 期次保存业务日期、映射、投注版本和开奖快照。
- 投注单拥有顺序排列的投注分项。
- 投注分项保存录入业务日期、市场、期次、规则、选项、基础注、费率、本金和结算结果快照。港澳混合单一次事务保存，各分项使用所属市场的独立开奖结果。
- 飞出关联原投注，并独立保存相应财务快照。
- 修改回执和提交标识用于识别重试。

## 金额与时间

金额持久化为整数分，录入最小精度为角。赔率按万分之一精度计算；百分比返水使用固定精度解析，避免二进制浮点作为记账依据。纯计算中的汇总及乘积必须经过安全范围检查。混合单提交与金额纠正同时校验分市场和整单的本金、最大派彩合计；金额纠正按期次标识排序锁定所有关联期次，防止并发修改绕过整单上限。

数据库时间使用 UTC；业务时钟为北京时间，业务日期在 06:00 切换。新澳门期号来自业务日期的年份与年内序数。香港期次使用独立内部标识，真实期号保存在开奖快照中；未开奖时可以跨业务日期继续录入。香港开奖后允许补录，开奖日次日北京时间 06:00 归档。浏览器显示按北京时间格式化。

新期次冻结适用映射；已接受开奖保存来源给出的生肖和波色。来源与预期映射不符形成警示，不能悄悄用最新配置改写历史快照。

## 写入与重试

提交先检查 request_id 与请求内容摘要，再锁定期次并再次检查重试。玩法被锁定后验证启用状态与版本。全部分项通过领域计划后才写入账本、学习偏好及审计。

错误发生在事务内时整单回滚。同一个标识与相同内容返回已提交的记录；不同内容使用同一个标识产生冲突。成功回执可在期次切换、玩法变更后恢复。

金额纠正与飞出使用修订版本及独立请求标识；同一条原投注的有效飞出不能超出允许金额。撤销和统计必须沿用原快照，不能重新应用最新费率。

## 结算与日报

期次状态包括 `pending`、`settling`、`settled`、`missing`。首个有效开奖被冻结，冲突开奖记录警示。结算和相关账本在同一事务内更新，重复结算不得重复派彩。

`bets.entry_date` 在录入时冻结，按北京时间 06:00 切日。概览、统计、历史及对账导出按此日期汇总，不按香港待开奖期次的起始日期汇总。香港开奖后回填原日期的派彩及净额；存在未结算分项时不能把未知派彩按零计算净额。飞出沿用原投注的日期。

`/days` 和 `/days/{id}` 使用新澳门日期期次作为日报标识；记录、统计和导出通过 `combined=true` 使用同一日期范围。读取在事务中按顺序锁定日期锚点和关联市场期次，写入也遵守此锁顺序，避免混合快照。每条记录保留市场、录入日期及开奖快照中的实际期号。

迁移 `0015_entry_business_date.sql` 为旧记录补齐日期：新澳门使用所属期次日期，混合单使用单头的新澳门日期，独立香港投注按 UTC 创建时间换算。风险预测模块及接口已移除；旧迁移中的风险列只为兼容既有数据库保留，不再读取或调度。

## 首页显示减出

`bettor_display_ratios` 保存共享账本中投注人名称和首页显示比例（百分比精确到 0.01%，范围 0–100%），与玩法归属、投注快照及财务结算无关；未配置时按 100% 计算。新建名称可用于录入提示。协作双方共用比例，关联前的个人账本保持隔离。首页先按投注人、市场和项目汇总原受注，再按比例四舍五入到分并汇总各投注人，最后应用该视图已有的累计减出。修改比例立即重算当前业务日已有投注；比例降低至累计减出以下时，显示金额为零，减出仍保留。原始受注接口和账本继续使用未修正金额。

`received_display_states` 按日报日期锚点、服务端确定的记录范围、市场保存累计减出和独立修订号；三类板块分别维护49、12、10个整数分金额。全部协作记录使用共享范围，仅本人使用会话账户标识；不同客户数据库及关联前账本不互通。`received_display_changes` 保存提交摘要、比例修正后的受注与前后减出快照及回执，随日期锚点级联清理。

`/periods/{id}/received-distribution` 继续返回原受注分布；首页单独使用 `/periods/{id}/received-display`。每项显示为比例修正后的受注减累计减出，最低为零。后续录入自然累加，撤销、退款或金额纠正使原受注下降时不产生负显示，累计减出仍保留至恢复显示或切日。新业务日使用新的日期锚点，不继承减出；旧日期只读。此口径不进入投注、飞出、结算、财务审计或账单，也不递增期次投注版本。

减出事务先按日报顺序锁定期次，再锁定对应显示状态；读取原受注及校验余额在同一事务完成。每批项目不得重复或超额，全部通过才保存。独立修订号阻止并发覆盖，提交标识和包含会话账户的摘要保证重试幂等；已成功的相同请求可在切日后恢复。接收期间新增投注不使显示修订号失效，服务端仍按新鲜余额校验。恢复显示只清除指定市场、指定板块。

## 恢复与删除

发布文件与持久化状态分开。完整备份代次包含控制库和客户库，并有文件摘要清单；恢复前校验路径、完整性及擦除回执。

永久删除和历史清除有跨数据库、文件系统的生命周期。独立擦除回执不能因恢复旧 SQL 备份而回退。测试这些路径时，同时检查库、用户、会话、备份和控制状态。

备份清单包含所有协作账本及其数据库身份，恢复同时重建私有与协作数据库。关联后的历史清理作用于协作账本，并以协作标识保存独立擦除回执；个人旧账保留。删除一个协作者时，其私有账本及账户删除，共享账本由其余成员继续保留；最后一个成员删除时，才删除共享数据库、用户和备份，并留下共享标识的删除回执。

迁移位于 `backend/migrations/`，SQLx 检查已执行版本和摘要。部署先启动运营端完成迁移；客户端只验证 schema。应用回滚需要相同迁移契约或配套数据库恢复。

港澳接口均从期次业务日期的北京时间 21:34 起，每隔 60 秒拉取。香港另需存在已入账且未撤销的有效投注；仅预览、提交失败或全部撤销时不请求香港接口，21:34 后首次入账则在下一次任务检查时开始。全部撤销后跨天重新入账，按重新录入的业务日期启动并清除旧的抓取状态。香港仍有有效投注但未开奖时保留同一期并跨天继续追踪，接受有效开奖后停止拉取。

香港同年期号必须为上一期加一，同时开奖日期必须为北京时间当天且时间不晚于当前时刻；跨年使用接口实际期号。早于待开奖期次起始日期的历史结果可以更新上一期，不能跳过已有待结算投注对应的开奖。历史清理保留尚未归档的香港期次及其混合单关联期次和录入日期锚点，先删除全部子账本再删除单头。
