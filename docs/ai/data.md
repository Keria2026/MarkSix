# 数据与一致性

## 数据归属

控制库拥有 `hosted_accounts`、`hosted_sessions`、`hosted_codes`、`authority_administrators`、`authority_sessions`、`authority_audit`、`hosted_deletions`。客户数据库拥有业务管理员、会话、玩法及版本、映射、期次、投注单、投注、飞出、修改回执、偏好与审计。

运营服务拥有开通客户数据库与数据库用户的能力。客户服务使用受限控制库身份，再通过验证后的账号租用独立客户连接池。每个客户库由独立 MySQL 用户访问。

浏览器中的“投注人”不产生平台账号，也不能选择其他客户数据库。导出、搜索、回执查询和偏好查询均位于当前客户上下文。

## 业务对象关系

- 玩法保存当前规则；玩法版本保存历次配置。
- 期次保存业务日期、映射、投注版本、风险状态和开奖快照。
- 投注单拥有顺序排列的投注分项。
- 投注分项保存市场、期次、规则、选项、基础注、费率、本金和结算结果快照。港澳混合单一次事务保存，各分项使用所属市场的独立开奖与风险结果。
- 飞出关联原投注，并独立保存相应财务快照。
- 修改回执和提交标识用于识别重试。

## 金额与时间

金额持久化为整数分，录入最小精度为角。赔率按万分之一精度计算；百分比返水使用固定精度解析，避免二进制浮点作为记账依据。纯计算中的汇总及乘积必须经过安全范围检查。混合单提交与金额纠正同时校验分市场和整单的本金、最大派彩合计；金额纠正按期次标识排序锁定所有关联期次，防止并发修改绕过整单上限。

数据库时间使用 UTC；业务时钟为北京时间，业务日期在 06:00 切换。新澳门期号来自业务日期的年份与年内序数。香港期次使用独立内部标识，真实期号保存在开奖快照中；未开奖时可以跨业务日期继续录入。香港开奖后允许补录，开奖日次日北京时间 06:00 归档。浏览器显示按北京时间格式化。

新期次冻结适用映射；已接受开奖保存来源给出的生肖和波色。来源与预期映射不符形成警示，不能悄悄用最新配置改写历史快照。

## 写入与重试

提交先检查 request_id 与请求内容摘要，再锁定期次并再次检查重试。玩法被锁定后验证启用状态与版本。全部分项通过领域计划后才写入账本、学习偏好及审计。

错误发生在事务内时整单回滚。同一个标识与相同内容返回已提交的记录；不同内容使用同一个标识产生冲突。成功回执可在期次切换、玩法变更后恢复。

金额纠正与飞出使用修订版本及独立请求标识；同一条原投注的有效飞出不能超出允许金额。撤销和统计必须沿用原快照，不能重新应用最新费率。

## 结算与风险

期次状态包括 `pending`、`settling`、`settled`、`missing`。首个有效开奖被冻结，冲突开奖记录警示。结算和相关账本在同一事务内更新，重复结算不得重复派彩。

风险结果通过期次、投注版本及任务标识隔离。投注变更使旧结果过期；取消、超时或保存失败不能发布旧结果。进程重启恢复持久化中的未完成任务。

## 恢复与删除

发布文件与持久化状态分开。完整备份代次包含控制库和客户库，并有文件摘要清单；恢复前校验路径、完整性及擦除回执。

永久删除和历史清除有跨数据库、文件系统的生命周期。独立擦除回执不能因恢复旧 SQL 备份而回退。测试这些路径时，同时检查库、用户、会话、备份和控制状态。

迁移位于 `backend/migrations/`，SQLx 检查已执行版本和摘要。部署先启动运营端完成迁移；客户端只验证 schema。应用回滚需要相同迁移契约或配套数据库恢复。

港澳接口均从期次业务日期的北京时间 21:34 起，每隔 60 秒拉取。香港另需存在已入账且未撤销的有效投注；仅预览、提交失败或全部撤销时不请求香港接口，21:34 后首次入账则在下一次任务检查时开始。全部撤销后跨天重新入账，按重新录入的业务日期启动并清除旧的抓取状态。香港仍有有效投注但未开奖时保留同一期并跨天继续追踪，接受有效开奖后停止拉取。

香港同年期号必须为上一期加一，同时开奖日期必须为北京时间当天且时间不晚于当前时刻；跨年使用接口实际期号。早于待开奖期次起始日期的历史结果可以更新上一期，不能跳过已有待结算投注对应的开奖。历史清理保留尚未归档的香港期次及其混合单关联期次，先删除全部子账本再删除单头。
