# 文本录注

入口：录入投注 → 文本录注。一份粘贴文本始终是一张投注单，换行、不同玩法和多个原文片段都是这张单的分项；不会按行自动拆单。达到容量上限时拒绝整单，不分批写入。

## 操作流程

1. 粘贴投注原文。
2. 点击“校验”，打开“确认投注单”弹窗。原文只在当前账号的浏览器内存中解析，不调用外部模型。
3. 在弹窗填写投注人、核对玩法和各项投注；特码可选择已配置的费率方案。精确匹配的玩法直接使用；已知简称及唯一优先建议自动选中。无法确认的简称、缺金额与歧义直接显示在对应项；修正后自动调用 Rust 只读规划器校验，展示基础注数和总本金，无需额外点击预览或勾选确认。
4. 点击“确认录入”。一次 `/api/slips` 请求原子保存所有分项，并默认记住已确认的简称和金额习惯；网络失败重试相同内容时沿用请求编号。

修改原文后重新点击“校验”。弹窗内修改投注人、玩法、投注项或金额会立即使旧校验失效，并在输入稳定后重新校验；自动校验不写投注、审计或学习记录。旧响应、关闭后返回的响应及账号切换后的响应不能重新启用确认。校验未完成或任一分项不合法时，“确认录入”不可用；网络错误可在弹窗重试校验。提交期间禁用编辑和关闭，避免重复提交或丢失处理状态。

主动清空投注内容会将该项标记为“不录入”，也可直接移除该项；剩余有效项可以继续确认。原文自带的缺对象或缺金额仍标记为错误，不自动排除。排除项不参与金额、校验和习惯保存；全部排除时禁止空单提交。错误项显示“待处理”，底部醒目列出需要处理的项号，点击可聚焦首个待修正字段。

返回修改、Escape 或关闭弹窗保留当前账号的原文和修正草稿，焦点返回“校验”。离开录注页后返回仍保留草稿；退出、授权失效或账号切换时销毁工作台并清理弹窗和草稿。页面刷新不持久化原文。超过整单容量限制会拒绝，不自动拆单。

## 前台剪切板识别

文本录注开启且当前期次可录入时，工作台首次进入前台、窗口重新获得焦点或页面恢复可见会读取最新剪切板文本；不定时轮询、不读取历史剪切板。原文具有已知玩法、投注对象与金额时自动打开同一个确认弹窗，并按现有规则校验。无关文字忽略，用户仍须补齐投注人并点击确认录入；自动识别不提交投注。

已有文本草稿、正在提交或其他弹窗打开时不覆盖当前操作。关闭文本模块、退出账号及授权失效时销毁监听器，晚到的读取结果不再处理。浏览器可能要求首次授权；读取失败时提示使用顶部“读取剪切板投注”按钮重试授权，也可直接粘贴原文。

成功录入后，按客户账号在浏览器保存最后一份完整原文的 SHA-256 摘要。再次读取完全相同的文本时跳过，刷新和同源标签页共用此摘要；失败和取消不更新摘要。摘要不能替代服务端请求编号幂等，仍由 `/api/slips` 保证同次请求重试去重。不保存剪切板明文到 localStorage，浏览器禁用存储时禁止发送新的文本投注，提示允许本站存储提交标识后重试。

## 刷新后的提交恢复

文本投注发送前按账号保存待处理请求编号及原文 SHA-256 摘要，不保存原文或投注明细。发送前存储失败则拒绝提交。工作台初始化以及再次确认时，通过 `GET /api/slips/submission/{request_id}` 查询本客户的提交结果：已经入账则记住成功摘要并清理待处理编号，不再次发送；尚未入账时，原文重试沿用原编号。旧提交未确认前，新的不同原文不能覆盖其编号。账号退出不删除未确认编号，避免再次登录后重复入账。

## 领域语义解析

解析器按词法识别、分项组装、业务转换三个阶段工作，源码分别位于 `frontend/src/lib/text-entry/lexer.ts`、`parser.ts`、`compiler.ts`，`text-entry.ts` 只保留外部接口与账号习惯。旧的遇到玩法词立即切段的扫描器已移除。

隐含玩法根据投注对象类别匹配当前已启用配置：`3尾5000`、`4尾500` 选择唯一的单尾玩法，`红波100`、`藍波各500` 选择唯一的单波色玩法；大小和单双对象也采用同样规则。多候选不自动猜选。裸号码和裸生肖仍可能对应多个玩法，不据此自动指定玩法。`尾中0尾各100` 中的尾是对象后缀，`二尾连3尾4尾各100` 中两个尾均保留在同一组。

词法阶段识别玩法、生肖／号码、金额标记、币种、复式／包肖／拖、开奖标记、括号及连接词，保留 Unicode 规范化前的原文位置。分项阶段从左到右收集玩法、对象、金额，允许玩法后置及明确标记的金额前置。空格、换行与标点只提供边界提示，不能把未完成的分项拆碎；新的明确玩法会中断上一条缺字段的分项并保留错误。已经完成的分项可向后续省略玩法的分项传递玩法，复式、包肖与显式金额标记不传递。

原文收集完成后的 `*` 等无业务字段的纯符号尾段不生成独立投注，原文位置仍完整保留。包含未知文字的尾段附着到上一项供修正；包含玩法、对象或金额的未完成分项仍须核对，不能丢弃。`【】`、`{}`、`[]` 内的内容作为独立组，逐组校验玩法要求的数量，左右各有一个括号即可成组，不要求形状相同，`{01 02]`、`【01 02}` 均有效；缺少左／右括号、嵌套、空组或混合未分组对象仍阻止提交。

转换阶段使用当前已启用的玩法及版本，把修饰、对象及金额含义转为现有 `SlipLine`。单号、生肖、复式、拖、包肖继续复用已有计算模块与 Rust 规划器。号码和金额无法可靠区分、总额无法精确均分、未知词、重复或越界选项都阻止整单提交。

`vocabulary.ts` 统一管理玩法匹配：启用玩法的精确名称优先，然后是用户明确的领域含义、有效账号习惯，最后是唯一优先建议。精确重名或建议并列时仍需选择。使用本地 `pinyin-pro` 字典将汉字逐字转换成不带声调的拼音，繁体及同音字只在启用玩法或有效简称命中时参与匹配；原文不修改。唯一对应的玩法自动选择，多个同音玩法保留人工确认。生肖、金额单位及复式／拖运算符使用同一词法归一，例如 `嗎→马`、`托→拖`、`複→复式`，在弹窗修改投注项时也适用。字典不发送文本到外部服务。`一肖中／平特一肖／平特一肖／平特肖／平特+肖／一肖／肖中` 对应“一肖中”，`澳特／特／特码` 对应“特码”，`二中特` 对应“二中二含特”。`牛中5000` 的“中”只在单一生肖后表示“一肖中”。依据最新规则，`新澳门四肖／四肖` 对应已配置的“四肖中特”，覆盖此前每肖包特码的解释；当前 31 条默认配置不包含该玩法，没有配置时保留待确认，不替换成其他生肖玩法；每肖包特码应明确写成 `特码包肖兔龙虎蛇各100`。新澳、澳门、新澳门、澳作为开奖标记忽略，但最长玩法名称优先，不能把“澳特”或“新澳门四肖”拆碎。元、米、斤统一为元；冒号分隔玩法与对象，“下”和斜杠通常标记其后的金额，“复”开启复式，“各”为每号、每肖或每组金额。

## 支持语法与保守边界

| 写法                                               | 处理                                                                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `特码：07、18各25元`、`特：14/100`、`特07下250米`  | 各／各号／各数／各注／各组／个组／每个／每注／下／乘号／斜杠金额；已知简称自动匹配，未知简称须选择                       |
| `二有，兔狗，兔蛇，各500`                          | 同一片段内两组完整选项生成两个分项，仍在同一投注单中                                                                     |
| `三有牛龙羊260`                                    | 连写生肖及其后金额；号码可以跨行继续                                                                                     |
| `二中特：牛拖龙各15元`、`二中二06.18拖27.36各25`   | 拖投注复用当前玩法及当期生肖映射，不能固定每肖四个号码                                                                   |
| `三有复式牛虎兔龙各100`、`另复三有牛狗马猪各注600` | “复／复式”可在玩法前后，“另复”与后续玩法属于同一片段；四肖复式三有拆为 4 注，每注 600 元；超过玩法选项数量不自动猜为复式 |
| `特码100包狗`、`特码包狗100`                       | 每肖包号金额，由服务端按当期映射分配                                                                                     |
| `牛特500`、`牛特码500`                             | 玩法后置的特码生肖包号，每肖总额 500 元；按当期映射分配，不能固定每肖四个号码                                            |
| `牛中5000`                                         | 一肖中，牛，每注 5,000 元                                                                                                |
| `新澳门四肖 兔龙虎蛇100米`                         | 已配置四肖中特时四个生肖组成 1 注，每注 100 元；否则待确认                                                               |
| `特码：羊300`                                      | 每号／每肖含义未确认时阻止提交，可人工选择并记住                                                                         |
| `特码01 02共100`                                   | 总额可以精确均分到每注一角时转换；不能均分时要求明确每注金额，不舍入                                                     |
| `0203`、`01-03`、金额缺省、未知尾字                | 不猜分、不扩展范围、不补默认金额；修正后才能预览                                                                         |
| `托`、未确认的新玩法简称等                         | 明确修正为“拖”或选择实际玩法，没有已知含义或唯一建议时要求确认                                                           |

每单原文最多 12,000 字、100 个原文片段、100 个业务分项、合计 1,000 条基础注。所有服务端原有期次、金额、预算和容量限制继续生效。生肖包号与片段总额同时出现时要求进一步明确。

## 投注人的特码费率

确认弹窗对单号码特码提供“特码费率”选择，列出当前已启用玩法的名称、赔率和水位。使用已配置玩法及当前版本，复用原有金额规划和快照，不在文本中直接修改费率。

成功录入时，将所选特码玩法和已确认的金额方式与投注人关联，和投注单处于同一事务。下一次输入同一投注人的通用特码表达，自动匹配该关联。不同投注人及不同客户独立；原文明确写出具体费率玩法名时优先保留该名称。不同费率玩法混合在一张单中且没有统一选择时，不建立含糊关联。

匹配完成前禁止确认，切换投注人、关闭弹窗或账号失效时取消旧请求，晚到响应不能覆盖当前选择。匹配失败时可在弹窗重试。主动选择其他费率并成功录入后更新关联；失败、预览和取消不学习。玩法修改后的下一次匹配采用其当前版本，旧投注快照不变；删除、停用或改为非单号码特码后不再自动复用。该关联不会把某一投注人的费率写成其他人的通用简称习惯。

## 自学习

学习单位是登录客户账号，不是跨客户共享的数据，也不是按投注人自动归因。整单成功提交后，默认将已确认的简称、玩法 ID、玩法版本及人工选择的金额习惯保存到客户库，无需额外勾选。识别和预览不会写入习惯。

- 投注保存和习惯更新处于同一事务；无效分项、无效学习条目或容量超限会全部回滚。
- 每账号最多 200 个条目。同一简称在一张单中出现冲突解释时不学习该简称。
- 下次自动复用已确认的对应关系，仍须核对整单；原文明示的“各／共／每肖”优先于历史习惯。
- 不学习金额缺省值、赔率、反水、开奖号码或未经确认的错误解析。
- 玩法变更版本、停用或删除后，旧习惯不参与匹配；列表标记失效，用户可重新确认或“忘记”。
- 忘记只删除习惯，不修改历史投注。改密、续期与停用不删除习惯；永久删除账号时随客户数据库清除，见[账号授权](accounts.md)。

这是一版确定性解析和确认式学习，不是大语言模型或可自行训练新语法的模型。任意自由表达、未收录语法仍可能需要手工修正。

## 合成样本训练与评估

根据提供的真实文件整理领域语法，再以独立的投注结构生成 5,000 条合成文本，覆盖 41 类表达：玩法前后置、跨行号码、整组共用金额、复式、拖、包肖、各注／总额／币种、全角数字、无意义星号尾段、独立及混合括号组、拼音／繁体变体和精确费率名称，以及缺金额、重复、粘连号码、歧义、未知词与错误总额等拒绝样本。原始文件保持在用户私有路径；生成清单只记录来源摘要、字符数与非空行数，不复制原始资料。

每条样本先确定玩法、对象、每注或包肖金额、组合方式与当期映射，再渲染文本。标准答案包含完整分项、注数和整数分本金；生成器不导入生产解析器，避免把解析器自身输出当作答案。生成内容没有调用模型，也不构成神经网络预训练。

训练集 3,500 条、验证集 750 条、测试集 750 条。三个集合的文本、语义分组和渲染模板互不重叠，但共享人工整理的领域语法，因此合成测试通过不能代表任意真实文本的识别率。新增真实语法应先确认含义，补独立标准答案，再扩充生成器。

```bash
# 仓库根目录；最后一个参数仅用于记录私有来源信息，不复制原文
bun scripts/generate_text_entry.ts test-results/text-entry-corpus /私有路径/原始真实数据.txt
# CI 无需真实文件，使用已经整理好的语法确定性重建相同语料
bun scripts/generate_text_entry.ts test-results/text-entry-corpus
bun scripts/train_text_entry.ts test-results/text-entry-corpus/train.jsonl
bun scripts/evaluate_text_entry.ts test-results/text-entry-corpus/train.jsonl test-results/text-entry-corpus/train-report.json
bun scripts/evaluate_text_entry.ts test-results/text-entry-corpus/validation.jsonl test-results/text-entry-corpus/validation-report.json
bun scripts/evaluate_text_entry.ts test-results/text-entry-corpus/test.jsonl test-results/text-entry-corpus/test-report.json
```

训练脚本只接受 schema 2 的带标签合成训练集，明确拒绝验证集和测试集。它根据独立标签统计简称候选，生成 `frontend/src/lib/generated/text-entry-candidates.json`，不调用解析器对齐标签，不直接更新客户习惯，也不学习金额、赔率或缺省投注。产物禁止手工编辑。前端使用该候选列表自动选择唯一优先建议；没有可用建议、建议并列或对应玩法不可用时要求人工选择。账号习惯只在相同玩法版本内复用。

评估同时比较玩法、选项、复式／拖／包肖、金额、基础注数和整数分本金，单独统计错误放行与错误阻断；错误放行、字段不符或本金不符都会使命令失败。CI 会重建语料、检查候选产物一致性并评估三个集合。原文及大批语料保存在仓库忽略的 `test-results/`，不会提交或发送到外部服务。

## 接口与数据库

沿用项目现有 `/api` 和 snake_case 契约；未引入新框架或数据库。

| 接口                                         | 契约                                                                                                                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/slips/preview`                    | `{period,bettor,items}`；items 与现有组合单分项一致。返回 `{valid,items:[{units,stake,error}],units,stake,error}`，stake 单位为分；过期／不存在期次返回 409，格式或数量错误返回 422，分项错误列入响应且 valid=false |
| `POST /api/slips`                            | 增加可选 `text_preferences:[{alias,play_id,play_version,amount_mode}]`；空列表省略以保持已有请求哈希。金额方式为 auto、each、package、total；条目必须绑定本单实际玩法                                               |
| `GET /api/text-entry/preferences`            | 返回当前客户的习惯列表，包括可手动删除的失效条目；客户端仅复用有效玩法及相同版本的条目                                                                                                                              |
| `DELETE /api/text-entry/preferences/{alias}` | URL 编码简称；仅删除当前客户条目，重复删除仍成功                                                                                                                                                                    |

`POST /api/text-entry/bettor-preference` 使用 `{bettor}` 查当前客户的特码关联，返回 `{preference:null|{play_id,play_version,amount_mode}}`。`POST /api/slips` 的 `entry_mode` 为 `manual` 或 `text`（缺省 manual），文本录注发送 text；可附带 `bettor_preference:{play_id,play_version,amount_mode}`，须绑定本单实际使用的有效单号码特码。

迁移 `0013_customer_preferences.sql` 增加 `module_features` 和 `bettor_play_preferences`。`GET /api/bootstrap`、`GET /api/settings` 返回 `features:{layoffs,manual_entry,text_entry,entry_mode}`；`PUT /api/settings/features` 更新三个布尔开关，`PUT /api/settings/entry-mode` 保存已开启的录注方式。默认飞出关闭、两种录注开启、最近方式 manual。文本预览和新增投注受服务端开关约束；接口沿用现有 `/api` 与 snake_case 契约。

迁移 `0012_text_entry_preferences.sql` 新建习惯表，不修改已有投注或快照。简称按精确字符区分，数据库读取显式转换为 UTF-8 文本。auth 启动时迁移控制库及客户库，之后启动 MarkSix；测试仅使用独立 marksix_test。回退仍遵循[部署指南](../deployment/vps.md)的迁移契约检查，不能通过删除已执行迁移来回退。

## 界面约定

延续现有玻璃面板、原生带标签的 input／select、`button`／`segmented` 样式和 `createRequestScope`。主页面只提供原文与“校验”；复用共享原生 Modal 核对分项。每项使用独立圆角边框，错误项同时显示红色边框和待处理标记；修正字段采用紧凑间距。桌面并排呈现原文与修正，720 像素及以下改为纵向排列；弹窗内滚动，底部注数、总本金和确认操作保持可见。源码中的 `app.css` 是视觉 token 的事实来源，不另建重复组件体系。错误紧邻对应片段，金额与注数以服务端预览为准；成功提示复用工作台通知。原文不进入 URL、localStorage、日志或浏览器追踪记录。
