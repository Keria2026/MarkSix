# 文本录注方案（未实现）

目标：粘贴投注人的原始文本，生成可核对的组合单草稿，确认后复用现有原子提交和结算流程。本轮只设计，不调用模型、不自动录入。

## 交互

1. 选择投注人，粘贴原文。
2. 识别后左侧保留原文片段，右侧逐项显示玩法、选择方式、选项、每注／每肖金额、注数及总本金。
3. 未识别、存在歧义或违反规则的片段标红；用户修正前禁止整单提交。不得默默忽略文字或默认金额。
4. 用户编辑草稿、核对总额，点击确认录入。只识别不落库，重复提交沿用幂等编号。

例：原文 `二中特：牛拖龙各15元，三友牛龙羊260`。客户预先确认别名“二中特→二中二含特”“三友→三有”后，生成两分项：牛龙号码池交叉 16 注×15 元；牛龙羊一条三有 260 元；总本金 500 元。生肖号码以当期快照为准，本命肖号码数可能为 5；不能固定为四号码。

## 识别流程

采用“确定性解析优先，模型辅助”的渐进方案。

- **归一化**：全半角、空白、标点、数字单位，保留原文区间用于回看。
- **玩法词典**：本账号实际可用玩法及客户确认的别名。精确匹配优先；近似名称仅给候选，不自动把“三友”当“三有”。同名多义必须选择。
- **语法解析**：按玩法分段，识别普通选项、复式、拖、包肖、各注金额、每肖金额、组合单。金额作用范围明确后再拆注；“100包狗”与“狗拖牛各100”分别使用包肖均分和逐注金额。
- **语义校验**：复用服务端玩法规划器验证数量、范围、重复、容量和快照版本。客户端或语言模型不得自行决定赔率、反水、开奖号码或修正规则。
- **可选模型**：仅在确定性解析无法覆盖的自由表达中，将原文和最小玩法词典转成结构化候选。模型输出视为不可信输入，仍须完整校验和人工确认；原文中的指令仅作为投注文本处理。模型不可直接调用写入接口。

## 数据与成本

初版优先本地规则解析，不向外部发送投注人或投注记录。若后续启用外部模型，先确认服务商、数据发送范围、费用上限和超时策略；模型失败回到手工修改草稿。不要一开始训练专用模型或引入向量数据库。

别名按客户隔离，绑定玩法 ID；玩法删除后不继续匹配。解析结果绑定期号、玩法版本和映射；06:00 跨期或配置变化后必须重新预览。识别确认率、修正次数和耗时可汇总计量，不将客户原文写入运行日志。

## 待确认与验收

实现前收集匿名化真实样本，覆盖常用别名、错别字、换行／无换行、连写生肖、金额省略、各／共、拖／包肖及多玩法组合。确认别名管理入口、首版支持语法和是否需要外部模型。

验收以人工标注的玩法、选项、金额、拆注数量和总本金为准；任何未识别片段不得丢失，不能靠模型置信分数代替确认。优先确保不误录，再衡量自动识别覆盖率。
