# 文本录注第一版

入口：录入投注 → 文本录注。一份粘贴文本始终是一张投注单，换行、不同玩法和多个原文片段都是这张单的分项；不会按行自动拆单。达到容量上限时拒绝整单，不分批写入。

## 操作流程

1. 填写投注人并粘贴原文，点击“识别整单”。原文只在当前账号的浏览器内存中解析，不调用外部模型。
2. 核对本单简称对应的玩法。精确名称直接匹配，未确认简称保持未选择；合成样本产生的建议只调整候选排序，必须人工确认。
3. 左侧回看原文，右侧修正投注项、金额和金额含义。无法识别的尾部文字、缺金额、连写号码、重复选项和歧义不会忽略。未注明玩法的片段可以手工选择玩法并补充要记住的简称。
4. 点击“校验并预览整单”。Rust 规划器验证所有分项，返回注数和整数分本金；预览不写投注、审计或学习记录，也不执行风险求解。
5. 勾选已核对并确认录入。一次 `/api/slips` 请求原子保存所有分项；网络失败重试相同内容时沿用请求编号。即使只有一个分项，也保存为一张组合单。

修改原文后必须重新识别；修正草稿、改投注人、切期、映射或玩法版本变化后，必须重新预览。离开录注页后返回会保留当前账号的草稿；退出、授权失效或账号切换时销毁工作台并清理草稿。页面刷新不持久化原文。

## 支持语法与保守边界

| 写法                                              | 处理                                                                         |
| ------------------------------------------------- | ---------------------------------------------------------------------------- |
| `特码：07、18各25元`、`特：14/100`、`特07下250米` | 各／各号／各数／各注／各组／个组／每个／每注／下／乘号／斜杠金额；简称须确认 |
| `二有，兔狗，兔蛇，各500`                         | 同一片段内两组完整选项生成两个分项，仍在同一投注单中                         |
| `三有牛龙羊260`                                   | 连写生肖及其后金额；号码可以跨行继续                                         |
| `二中特：牛拖龙各15元`、`二中二06.18拖27.36各25`  | 拖投注复用当前玩法及当期生肖映射，不能固定每肖四个号码                       |
| `三有复式牛虎兔龙各100`                           | 明确声明复式后拆注；超过玩法选项数量不自动猜为复式                           |
| `特码100包狗`、`特码包狗100`                      | 每肖包号金额，由服务端按当期映射分配                                         |
| `特码：羊300`                                     | 每号／每肖含义未确认时阻止提交，可人工选择并记住                             |
| `特码01 02共100`                                  | 总额可以精确均分到每注一角时转换；不能均分时要求明确每注金额，不舍入         |
| `0203`、`01-03`、`牛中5000`、金额缺省、未知尾字   | 不猜分、不扩展范围、不补默认金额；修正后才能预览                             |
| `托`、含糊的“新澳门四肖”等                        | 明确修正为“拖”或选择实际玩法，不根据类似名称自动认定业务含义                 |

每单原文最多 12,000 字、100 个原文片段、100 个业务分项、合计 1,000 条基础注。所有服务端原有期次、金额、预算和容量限制继续生效。生肖包号与片段总额同时出现时要求进一步明确。

## 自学习

学习单位是登录客户账号，不是跨客户共享的数据，也不是按投注人自动归因。勾选“确认录入后，记住本账号的玩法简称与金额习惯”时，成功提交才将简称、玩法 ID、玩法版本及人工选择的金额习惯保存到客户库。

- 投注保存和习惯更新处于同一事务；无效分项、无效学习条目或容量超限会全部回滚。
- 每账号最多 200 个条目。同一简称在一张单中出现冲突解释时不学习该简称。
- 下次自动复用已确认的对应关系，仍须核对整单；原文明示的“各／共／每肖”优先于历史习惯。
- 不学习金额缺省值、赔率、反水、开奖号码或未经确认的错误解析。
- 玩法变更版本、停用或删除后，旧习惯不参与匹配；列表标记失效，用户可重新确认或“忘记”。
- 忘记只删除习惯，不修改历史投注。改密、续期与停用不删除习惯；永久删除账号时随客户数据库清除，见[账号授权](accounts.md)。

这是一版确定性解析和确认式学习，不是大语言模型或可自行训练新语法的模型。任意自由表达、未收录语法仍可能需要手工修正。

## 合成样本训练与评估

提供的 300 条 JSONL 记录用于离线词汇候选训练和回归评估。训练仅接受显式标记 `is_synthetic=true`、带 `items` 标注的数据；只有片段数与标注数对齐的记录进入候选频次统计。不能可靠映射到项目实际玩法的标签不训练为默认规则。

当前候选产物来自 150 条可对齐记录、143 个可映射标注，包含 25 个简称的候选频次。产物只含词条、候选名称、计数和源文件 SHA256，不包含原始投注文本、金额或账号资料，也不自动写入任何客户的习惯库。

```bash
bun scripts/train_text_entry.ts /私有路径/liuhe_synthetic_betting_records.jsonl
bun scripts/evaluate_text_entry.ts /私有路径/liuhe_synthetic_betting_records.jsonl
```

生成位置：`frontend/src/lib/generated/text-entry-candidates.json`，禁止手工编辑。评估区分“可进入草稿”和“需要人工确认”；这不是识别准确率，也不能替代服务端校验。金额缺失的样本必须被阻止。真实文本文件留在用户原路径，没有复制进仓库或写入运行日志。

## 接口与数据库

沿用项目现有 `/api` 和 snake_case 契约；未引入新框架或数据库。

| 接口                                         | 契约                                                                                                                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/slips/preview`                    | `{period,bettor,items}`；items 与现有组合单分项一致。返回 `{valid,items:[{units,stake,error}],units,stake,error}`，stake 单位为分；过期／不存在期次返回 409，格式或数量错误返回 422，分项错误列入响应且 valid=false |
| `POST /api/slips`                            | 增加可选 `text_preferences:[{alias,play_id,play_version,amount_mode}]`；空列表省略以保持已有请求哈希。金额方式为 auto、each、package、total；条目必须绑定本单实际玩法                                               |
| `GET /api/text-entry/preferences`            | 返回当前客户的习惯列表，包括可手动删除的失效条目；客户端仅复用有效玩法及相同版本的条目                                                                                                                              |
| `DELETE /api/text-entry/preferences/{alias}` | URL 编码简称；仅删除当前客户条目，重复删除仍成功                                                                                                                                                                    |

迁移 `0012_text_entry_preferences.sql` 新建习惯表，不修改已有投注或快照。简称按精确字符区分，数据库读取显式转换为 UTF-8 文本。auth 启动时迁移控制库及客户库，之后启动 MarkSix；测试仅使用独立 marksix_test。回退仍遵循[部署指南](../deployment/vps.md)的迁移契约检查，不能通过删除已执行迁移来回退。

## 界面约定

延续现有玻璃面板、原生带标签的 input／select、`button`／`segmented` 样式和 `createRequestScope`。桌面并排呈现原文与修正，720 像素及以下改为纵向排列；页面承担纵向滚动。源码中的 `app.css` 是视觉 token 的事实来源，不另建重复组件体系。错误紧邻对应片段，金额与注数以服务端预览为准；成功提示复用工作台通知。原文不进入 URL、localStorage、日志或浏览器追踪记录。
