## 1. 目标与第一版范围

系统供盘口方（庄家）使用，由一个管理员录入、管理和统计投注。第一版不关联投注者姓名或代号，不提供投注者账号或注册。

第一版包括：

1. 表单投注及复式组合明细。
2. 获取开奖、校验结果、自动结算与反水计算。
3. 本期盘口统计及开奖前精确风险极值。
4. 历史期次汇总与投注明细查询。
5. 管理员配置玩法、封盘时间、号码生肖映射和本命生肖。

系统记录和计算投注，不接入充值、提现或资金支付。金额均为人民币。界面使用简体中文。

投注表单展示投注者的收益；开奖页和历史统计展示盘口方的盈亏。页面必须明确标注口径，不统一使用含义不明确的“可赢金额”或“输赢金额”。

## 3. 领域对象与投注选项

### 3.1 投注记录和基础注

- 投注记录：管理员一次提交产生的记录。
- 基础注：独立判断中奖、计算含本返还及反水的最小单位。
- 非复式：一条记录包含一条基础注，使用本次选择的全部选项。
- 复式：从 n 个不同候选选项中取 k 个，生成全部 C(n,k) 个不同组合，每个组合是一条基础注。
- 每条基础注金额相同，表单填写的是每条基础注的本金，不是整条记录的总金额。
- 总本金 = 基础注条数 × 每注本金。
- 投注本金只能是整数，每注至少 1 元；不接受负数、零或小数。
- 选项不能重复。数字展示使用两位格式 01–49，内部应规范化，01 与 1 不能被视为不同号码。

例如，候选七生肖、复式五有、每注 100 元：C(7,5)=21 条基础注，总本金 2,100 元。默认展示记录汇总，可展开查看每个组合、金额、命中情况、适用赔率、返还、反水和盘口净盈亏。

### 3.2 可配置投注对象

| 对象 | 可选值 | 命中依据 |
| --- | --- | --- |
| 号码 | 01–49 | 对比范围内的开奖号码 |
| 生肖 | 鼠、牛、虎、兔、龙、蛇、马、羊、猴、鸡、狗、猪 | 对比范围内的开奖生肖 |
| 波色 | 红、蓝、绿 | 仅支持特码，以接口该项 wave 为准 |
| 尾数 | 0–9 尾 | 对比范围内号码的个位数 |
| 单双 | 单、双 | 对比范围内号码的数值奇偶性 |

例如，9 尾包括 09、19、29、39、49；0 尾包括 10、20、30、40。49 是单数，不设置和局或特殊退本规则。

## 4. 玩法配置与命中规则

管理员通过下拉选项和表单配置规则，不输入脚本或任意表达式。每个玩法只使用一种投注对象，不支持“红波且单数”等跨对象条件组合。

| 配置项 | 规则 |
| --- | --- |
| 名称 | 管理员自定义 |
| 投注对象 | 号码、生肖、波色、尾数或单双之一 |
| 对比范围 | 平码、特码或全部；波色仅可选特码 |
| 命中条件 | 全部命中、全部不命中、至少命中一个 |
| 数量关系 | 等于、少于等于、大于等于，即 =、≤、≥ |
| 数量阈值 q | 正整数，约束每条基础注选项数量 |
| 复式拆分数量 k | 正整数，必须符合该玩法的数量关系 |
| 普通赔率 | 含本金，正数，最多四位小数 |
| 反水比例 | 0%–100%，百分比最多两位小数 |
| 本命生肖特殊赔率 | 仅生肖玩法可启用；启用时配置正数含本赔率，最多四位小数 |

配置必须至少允许一个可提交的基础注数量。任何基础注不得超过该对象的不同选项总数，不允许空基础注。配置无法产生任何合法选择时，保存应被拒绝并说明原因。

### 4.1 数量关系与复式

数量关系检查的是基础注，而非复式候选池：

- 非复式：本次选项数量 m 必须满足 m 与 q 的配置关系，提交后全部 m 个选项构成一条基础注。
- 复式：配置的 k 必须满足该数量关系；本次候选数 n 必须至少为 k，生成全部 C(n,k) 个基础注。
- 非复式不自动把多个选项拆成单项投注。需要拆分时必须勾选复式。

| 示例 | 行为 |
| --- | --- |
| 一肖中，数量 =1、k=1，不勾复式 | 只能选择一个生肖 |
| 一肖中，数量 =1、k=1，勾选复式并选三个生肖 | 生成三条单生肖基础注 |
| 特码，数量 =1、k=1，复式选 01、02、03，每注 100 元 | 生成三条基础注，总本金 300 元 |
| 五有，数量 =5、k=5，不勾复式 | 必须恰好选择五个生肖 |
| 五有，数量 =5、k=5，复式选七个生肖 | 生成 21 个五生肖组合 |
| 数量 ≤5，不勾复式，选择四个选项 | 合法，形成一条四选项基础注；“全部命中”指这四个全部命中 |

### 4.2 命中条件

根据对比范围，从开奖结果中形成该投注对象的去重集合 D。一条基础注选项集合为 S，命中数量 h = |S ∩ D|：

- 全部命中：h = |S|。
- 全部不命中：h = 0。
- 至少命中一个：h ≥ 1。

同一个生肖、波色、尾数或单双在开奖范围中重复出现，只表示该选项被命中一次。每条基础注最多中奖一次，不按出现次数累计派奖。

平码是前六个开奖号码，不判断其排列顺序；特码是第七个号码；全部是六个平码加一个特码。

例：“平特一肖中”，对象生肖、范围全部、数量 =1、条件至少命中一个、普通赔率 2、反水 5%。所选生肖在七个开奖生肖中出现一次或多次，都只中奖一次。

### 4.3 特殊赔率和配置快照

- 特殊赔率仅适用于生肖玩法，由管理员按玩法选择是否启用。
- 每条中奖基础注单独判断是否包含本期本命生肖；包含时使用特殊赔率，否则使用普通赔率。
- 候选池包含本命生肖，不代表所有组合都使用特殊赔率。
- “全部不命中”的生肖玩法同样按此规则适用特殊赔率。
- 不中奖的基础注返还为零，仍按有效本金计算反水。

提交时保存玩法名称、对象、范围、命中条件、数量规则、复式 k、普通／特殊赔率、反水比例、本命生肖及该注适用赔率的快照。已有投注不随配置修改变化；后续配置只影响新投注，历史查看和重算沿用原快照。重算不能重复累计统计。

## 5. 期次、时间与投注生命周期

所有业务时间采用北京时间 Asia/Shanghai；以服务器收到请求的时间判定投注是否在窗口内。

| 事件 | 时间／规则 |
| --- | --- |
| 切换业务期次 | 每日 00:00 |
| 开始接受投注 | 08:00 |
| 默认封盘 | 21:28，可由管理员配置 |
| 开始获取开奖 | 21:34 |
| 抓取重试间隔 | 60 秒 |

### 5.1 期号

- 每个业务日期对应一期，期号为 YYYYDDD，DDD 为补足三位的年内日序号。
- 年内每天加一，新年重置为 YYYY001；闰年允许第 366 期。
- 首次启动按当前北京时间业务日期生成期号，无需已有上一期数据。
- 切换到新期不代表上一期已取得开奖或完成结算；多个期次可同时处于不同状态。
- 取得开奖时同时核对 expect 和 openTime 对应日期。期号或日期不匹配不能用于该目标期次结算，须提示异常并保留投注。

### 5.2 新增与撤销

- 接受区间为 [08:00, 当期封盘时间)，到达封盘时刻即不接受提交。
- 封盘前可以撤销整条记录，然后重新录入；原记录永久保留，不能直接修改金额或选项，不支持部分撤销。
- 封盘后禁止新增和撤销；当前期不重新开放。
- 封盘时间修改从下一期生效，每期保存自己的时间配置，不改变本期窗口。
- 撤销记录不计有效本金、返还、反水或有效投注容量。
- 每条记录明确区分有效待结算、已撤销、已结算，不将“未中奖”和“尚未结算”混用。
- 同一提交请求重试不能重复创建记录；管理员有意再次提交同样内容，可以产生新的独立记录。
- 后端在同一一致性边界内检查期次、时间、配置快照和容量，不能只依赖前端校验。

### 5.3 开奖抓取窗口与恢复

1. 从本期 21:34 开始抓取；失败、返回旧结果或未取得本期有效结果时，每 60 秒重试。
2. 跨过午夜继续抓取旧期，不能因为进入新业务日期就停止。
3. 取得本期有效结果后停止该期重试并结算。
4. 若响应中存在本期有效结果，优先处理本期结果；否则发现更晚期号的有效结果时停止旧期重试。
5. 即使没有发现更晚结果，到达下一期定时抓取时刻也停止旧期重试。
6. 截止仍缺失的旧期标记“开奖缺失”，保留投注及待结算本金，不计入已实现盈亏；新期照常运行。
7. 第一版不提供人工录入、导入或修改开奖结果。不伪造历史结果，不拿新期结果替旧期结算。
8. 重启后恢复尚在抓取窗口内的未结算期次；若已接受结果但结算中断，应恢复结算。已超过窗口且从未接受结果的期次标记开奖缺失。

建议期次状态至少包括：待开盘、接受投注、已封盘／待抓取、抓取中、结算中、已结算、开奖缺失。数据异常和结果冲突应单独记录错误原因，不通过伪造“已结算”掩盖。

## 6. 开奖接口及可信输入边界

接口：`https://macaumarksix.com/api/macaujc2.com`。必须保留 HTTPS/TLS 验证，处理网络失败、超时、非成功 HTTP 状态、非 JSON 响应及解析失败。

响应结构示例（用于说明字段格式，不作为固定测试开奖结果）：

```json
[
  {
    "expect": "2025123",
    "openTime": "2025-05-03 21:32:32",
    "type": "8",
    "openCode": "37,30,49,16,09,12,45",
    "wave": "blue,red,green,green,blue,red,red",
    "zodiac": "蛇,鼠,蛇,虎,雞,馬,雞",
    "verify": false
  }
]
```

- 根结构为数组，应遍历匹配目标期次，不假定结果位于第一项。
- expect 是字符串。openTime 按北京时间解析。
- openCode、wave、zodiac 是逗号分隔字符串，拆分后按索引一一对应。
- openCode 必须恰有七个互不重复的整数号码，范围 1–49，末项为特码。
- wave 必须恰有七项，且只能为 red、blue、green，转换为红、蓝、绿。
- zodiac 必须恰有七项且只属于十二生肖；龍、馬、雞、豬等繁体规范化为简体。
- 号码可去重校验，但不能对三个序列分别排序而破坏对应关系。
- expect、openTime 和目标业务日期必须一致；补结算校验目标期次日期，不校验抓取当天日期。
- 非必需附加字段不参与中奖计算；verify=false 不单独作为拒绝依据。接口字段缺失或不合法时不得结算。
- 实际结算使用接口的号码、生肖及波色。若合法接口数据与本地预测映射不同，明确提示差异，仍按接口结算。

同一期首次有效结果接受后不可更改。相同结果重复获取不能重复结算；不同结果提示冲突、保留首次已接受结果，不覆盖。保存原始响应、规范化结果和接受时间，便于查看来源与诊断。

开奖接受、基础注结果、记录汇总和期次汇总必须保持一致。结算中断后可以安全重试；读取页面不能出现部分结算的已实现净利，也不能重复累计返还或反水。

实测说明：需求澄清时接口一次返回了单条结果 expect=2026286、openTime=2026-10-13 21:32:32。该观察不构成历史查询、固定返回条数或全年连续供数的保证。

## 7. 返还、反水、金额精度与盈亏

### 7.1 基础注计算

设基础注本金为 a，适用含本赔率为 o，反水比例为 r（如 2% 对应 0.02）：

```text
中奖含本返还 = 中奖时 round_half_up(a × o, 2)，未中奖时为 0
反水 = 有效注 round_half_up(a × r, 2)，撤销注为 0
基础注盘口毛利 = 有效本金 − 中奖含本返还
基础注盘口净盈利 = 有效本金 − 中奖含本返还 − 反水
基础注投注者净盈利 = 中奖含本返还 + 反水 − 有效本金
```

- 所有有效投注无论中奖与否均有反水。反水不是只对输注计算。
- 赢注本金指中奖基础注本金，输注本金指未中奖基础注本金，不等于返还或盈利。
- 不设和局或和局退还本金。
- 赔率最多四位小数，反水百分比最多两位小数；超出精度的输入明确拒绝，不静默截断。
- 返还和反水分别在每条基础注上四舍五入到分，再进行记录、玩法和期次汇总，不能先汇总本金再舍入。
- 全程采用十进制定点／精确十进制计算，不使用二进制浮点处理金额。
- 输入和累加必须检查可表示范围，溢出时明确报错，不产生负数回绕或截断值。

### 7.2 记录与期次汇总

设全部有效基础注本金之和为 B，中奖含本返还之和为 P，反水之和为 R：

```text
有效本金 B = 赢注本金 + 输注本金（仅已结算时可这样拆分）
盘口毛利 = B − P
盘口净盈利 = B − P − R
投注者盈利（不含反水）= P − B
投注者净盈利（含反水）= P + R − B = −盘口净盈利
```

盘口净盈利正数代表庄家盈利，负数代表庄家亏损。历史列表和开奖页使用盘口口径；若详情另展示投注者收益，必须明确标注。

未开奖、开奖缺失和结算中的投注计入待结算本金，不计入已实现盈亏。未结算金额应显示“待结算”，不能显示为已实现零收益，也不能直接认定全输。预计反水可以展示，但只有完成结算后才进入该期已实现净利。

### 7.3 金额验收示例

通用汇总示例：21 条基础注，每注 100 元，含本赔率 10，某次结果中奖 3 条，反水 2%。总本金 2,100 元，返还 3,000 元，反水 42 元，投注者盈利不含反水 +900 元、含反水 +942 元，盘口净盈利 −942 元。

该示例用于验证金额汇总，不代表“七选五有”可以中三条。七选五有采用全部命中条件时，命中候选生肖的不同数量为 h，中奖基础注数为 C(h,5)，h<5 时为零；h=5、6、7 时分别为 1、6、21 条。

真实五有示例：候选生肖为马、鼠、牛、虎、兔、龙、蛇，全部范围，七选五有，每注 100 元；开奖号码为 01、13、07、06、05、04、03，对应生肖马、马、鼠、牛、虎、兔、龙。命中六个不同候选生肖，中奖 C(6,5)=6 条：

| 赔率配置 | 返还 | 反水 | 投注者净盈利 | 盘口净盈利 |
| --- | ---: | ---: | ---: | ---: |
| 普通赔率 10，无特殊赔率，反水 2% | 6,000.00 | 42.00 | +3,942.00 | −3,942.00 |
| 普通赔率 10，本命马特殊赔率 8，反水 2% | 5,000.00 | 42.00 | +2,942.00 | −2,942.00 |

第二行六条中奖组合中，五条包含马、每条返还 800 元，一条不包含马、返还 1,000 元。重复开奖生肖马不增加中奖次数。

舍入示例：三条基础注各 1 元、反水 0.5%，每条反水为 0.01 元，总反水为 0.03 元，不能按总本金计算成 0.02 元。

## 8. 开奖前精确风险与投注表单收益

### 8.1 合法预测开奖结果

风险预测使用本期固定的号码生肖映射、固定波色表，以及每条投注自己的规则和赔率快照。

合法预测结果为七个互不重复的 1–49 号码，其中一个是特码、另外六个是无序平码。生肖和波色按预测映射得到，尾数和单双由号码推导。不能独立拼凑互相矛盾的号码、生肖与波色，也不能让多个特码投注同时因为不同特码号码而中奖。

预测是“在本期配置映射成立的前提下”的精确极值。接口合法映射不同于配置时，实际结算仍以接口为准，页面提示预测依据与实际数据存在差异；不能声称预测覆盖任意异常映射。

### 8.2 本期盘口极值

对同一期全部有效基础注，在每个合法预测结果 d 下按实际结算规则得到 P(d)：

```text
盘口净盈亏 N(d) = B − P(d) − R
最佳结果净盈亏 = max N(d)
最坏结果净盈亏 = min N(d)
最大可能净盈利 = max(0, max N(d))
最大可能净亏损 = max(0, −min N(d))
```

- 页面展示有效本金、预计总反水、最大可能净盈利和最大可能净亏损。
- 为最佳和最坏情形各提供一个达到对应极值的示例开奖结果，明确标注平码和特码。
- 同时展示示例对应的有正负号净盈亏；若所有结果都亏损，说明没有盈利情形；若所有结果都盈利，说明没有亏损情形。
- 有多个相同极值结果时，只需返回一个合法示例。
- 没有有效投注时，上述金额均为零，不需要运行昂贵计算。
- 不能把每条投注单独最大返还相加，不能用抽样、局部搜索或估算结果冒充精确极值。

### 8.3 投注表单收益

- 当前表单独立于本期其他记录，基于同一个合法结果计算该记录的最大含本返还。
- 展示组合条数、总本金、预计反水、最大含本返还和最大净盈利（含反水）。
- 表单最大净盈利使用有正负号数值：最大含本返还 + 该记录反水 − 该记录总本金；若为负，应明确显示仍可能净亏损，不标作正收益。
- 复式不能假定所有基础注都能同时中奖；计算中或失败时显示状态，不填入猜测数值。
- 计算状态不替代提交时的后端规则和容量校验。

### 8.4 计算版本、超时与性能要求

- 每次计算绑定一个完整投注集合快照及本期映射，记录其版本、开始时间、完成时间和状态。
- 新增或撤销有效投注后立即使旧结果过期，触发最新快照计算。计算不阻塞继续录入。
- 旧任务晚完成不能覆盖新版本结果；允许取消或合并已被新版本替代的任务。
- 页面明确区分等待、计算中、已完成、已过期、超时和失败。过期结果如保留展示，必须标明，不能当作当前有效风险。
- 硬性性能验收目标：2 vCPU、1 GB 内存的 Ubuntu，整套服务共同运行，在容量上限范围内，没有被后续修改替代的一次快照，从触发计算到有效结果落库不超过 60 秒。
- 投注表单需要的精确收益计算也不能以估算替代，采用相同资源和正确性要求。
- 达到 60 秒仍未完成时标记超时，不发布部分或估算极值；超时意味着该次性能验收不通过，不能因错误提示正常就宣称达标。
- 性能目前未验证，必须在实现早期针对最大容量、混合玩法、复式与特殊赔率进行实测。基准包含 MySQL 和其他运行服务的内存，不能把 1 GB 全部视为计算进程可用。

六个平码无序且一个特码的合法号码结果空间为 C(49,6)×43=601,304,088。本文不要求逐一暴力枚举；实现者可以采用经过正确性验证的等价压缩、精确剪枝等方法，但不得改变结果或缩水支持范围来满足时间目标。

## 10. 页面与交互验收

### 10.1 投注页

提供玩法选择、规范化选项选择、复式开关、每注整数金额输入。玩法说明显示对象、范围、命中条件、数量关系、普通及特殊赔率、反水。

展示当前期号、北京时间、封盘时间及是否开放。规则不合法、组合或期次超限、已经封盘、配置已发生变化等提交失败必须说明具体原因，不能静默改变金额、选项或赔率。

提交成功展示记录编号及保存后的快照，可查看基础注明细。重复点击或请求重试不能重复录入。

### 10.2 本期开奖与盘口页

- 选择期次，展示业务日期、期号、状态、抓取状态及异常信息。
- 未开奖显示有效记录数、基础注数、本金、预计反水、精确极值状态及示例结果。
- 已开奖显示六个平码和一个特码，各号码的接口生肖及波色、开奖时间。
- 已结算显示有效本金、赢注本金、输注本金、中奖返还、总反水、毛利和净盈利。
- 按玩法分类展示记录；复式记录默认汇总，展开查看每条基础注。
- 撤销记录标记清楚，不混入有效统计；开奖缺失、冲突和映射差异可见。

### 10.3 历史统计页

按业务日期或期号查询，分页展示期次状态、有效本金、返还、反水、毛利、净盈利。可进入某期查看开奖结果、玩法汇总和投注及组合明细。

汇总已实现盈亏只包含完成结算的期次；待结算、开奖缺失和异常期次单独显示待结算本金。历史页面不能因玩法或映射配置修改而改变已结算结果。

### 10.4 配置页

提供玩法表单、封盘时间设置、未来生效的生肖映射及本命生肖配置。保存前显示字段错误和规则组合错误，说明已有投注不受玩法修改影响、封盘与映射的生效日期。

配置记录应可辨识版本和生效范围，以支持投注与历史快照查询。

## 11. 容量、一致性及逻辑数据要求

### 11.1 容量

- 每期最多 1,000 条未撤销记录、10,000 条有效基础注。
- 单次提交最多生成 1,000 条基础注。
- 撤销记录永久保留，不占有效投注容量；不提供删除审计记录的入口。
- 提交前展示组合数和总本金，超限明确拒绝，不截断组合，不只保存前若干条。
- 后端独立计算组合规模，在生成大量组合之前检查上限；并发提交必须正确维护期次总量。

## Windows 原生安装包（无需 Docker）

GitHub Actions 的 **Windows Native** 工作流构建 `MarkSix-Windows-Native-x64`：包含 Windows 原生后端、前端和 MySQL 数据库。在对应成功运行的 Artifacts 下载 ZIP，完整解压，首次安装 VC++ 运行库（包内 `vc_redist.x64.exe`），随后双击 `Install.cmd`。日常使用 `Start.cmd` / `Stop.cmd`，浏览器访问 `http://127.0.0.1:8088`。

支持 Windows 10/11 x64，使用本机用户进程，不依赖 Docker、WSL 或开发工具。数据存放 `%LOCALAPPDATA%\MarkSix`，凭据使用当前 Windows 用户的 DPAPI 加密。详情与备份、升级限制见 [原生部署说明](deploy/windows-native/README.md)。原 `MarkSix-Windows-x64` 工件仍为 Docker Desktop 版，请注意下载名称。
