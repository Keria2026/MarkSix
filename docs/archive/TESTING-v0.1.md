## 精确计算基准

`backend/examples/risk_bench.rs` 提供三组确定性的 10,000 基础注组合。每次结果都以同一结算器复核两个示例开奖结果，检查号码不重复。单独容器限制 1.4 vCPU、384 MiB，实测：

| 场景 | 精确计算耗时 | 搜索节点 |
| --- | ---: | ---: |
| 号码特码 | 1 ms | 49 |
| 生肖复式 | 16 ms | 12 |
| 号码、生肖、复式、尾数及单双混合 | 917 ms | 3,612,790 |

完整 Compose 部署共同运行时，将同一基准程序放入后端容器执行，三组分别为 0、9、715 ms。CPU 限额合计 2 核，内存限额合计 832 MiB；运行后内存快照约为 MySQL 192.6 MiB、后端 2.2 MiB、前端 6.1 MiB，三个容器均无 OOM。该快照不是历史峰值，也不包含宿主机开销。

这些是固定代表性样本，不是所有可配置组合的最坏情况证明。高分散、多条件的任意组合仍可能超时；超时只报告状态，不发布估算值或把旧结果当作当前结果。

## 验收边界

- 尚未在独立的 2 vCPU／1 GB Ubuntu 虚拟机上完成所有玩法分布、完整容量和持续并发的全面验收。说明书 A31 的总体性能要求目前不能判定为完全通过。
- 开奖异常、结算及恢复通过受控接口数据测试；没有等待真实开奖时刻进行长期联网连续运行验收。外部接口的未来可用性不由应用保证。
- 浏览器自动化使用 Chromium；Safari／Firefox 与辅助技术手工验收未完成。玻璃效果提供减少动态效果、减少透明度和高对比偏好样式。
- GitHub Actions 配置已经加入；以 GitHub 实际运行结果为准，不能把本地测试视为远端 CI 已通过。

复现命令与测试数据库清空规则见 [开发指南](DEVELOPMENT.md)。
