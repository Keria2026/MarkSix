# 系统架构

MarkSix 是 Ubuntu Docker 托管系统。客户工作台与 auth 管理端共用 Rust 镜像，通过不同进程、数据库权限和 Nginx 域名路由隔离。业务与金额规则见 [规范](../guides/betting.md)，生产操作见 [VPS 指南](../deployment/vps.md)。

## 组件及信任边界

- Nginx：TLS 终止、双域名转发、静态前端。应用和数据库端口仅在容器网络开放。
- MarkSix：中央会话验证后选择客户数据库，执行手工录注、账本查询、结算与风险任务。
- auth：客户账号、激活码、授权、数据库创建与永久删除；持有建库权限和备份目录。
- MySQL：控制库保存身份与核销；每客户独立业务库和数据库用户。

任何 URL、请求头和表单均不能直接选择客户数据库。中央账号检查包含会话、凭据版本、停用及期限；在单次请求内以内部扩展传递验证结果，扩展必须与目标客户匹配，不能从 HTTP 头构造。没有跨请求授权缓存。

客户服务将已认证的历史清空与自助改密请求转发到固定 auth 地址，不挂载备份目录。清空与删除凭据独立于 SQL 备份保留，防止恢复已删除数据。

## 并发和资源

目标主机为 2 vCPU、1 GB 内存、40 GB 磁盘，目标 200 在线；容量需要实测，不能由配置额度推断。

热账本最多 12 个，每池最多 2 个连接；8 个业务并发槽。请求与风险任务固定其账本上下文，空闲账本按 LRU 淘汰。每个热账本复用 Router；冷载入串行处理，数据库等待和关闭连接不占全局账本缓存锁。

请求接收时间在进入资源队列前捕获，业务层不得覆盖。全局精确风险计算并发为 1。开奖成功及失败响应均共享短时缓存，避免外部故障导致按客户重复请求。风险任务状态机见规范。

## 前端边界

App 管理客户登录与授权生命周期；有效账号内挂载 Workspace，退出／失效时整体销毁。投注表单、玩法编辑和系统配置分别持有自己的草稿及请求作用域。作用域销毁后取消请求，并在返回时再次检查有效性。

Management 管理 auth 界面，退出／失效清除客户列表、激活码、操作草稿和弹窗。所有页面共享 Glass 视觉与减少动态效果设置。

## 单据与导出边界

组合单的父记录只持有收据身份及提交幂等信息，子分项复用原有基础注、结算和飞出模型；父记录不参与金额计算，避免重复计账。按单分页与导出先锁定期次，确保多步读取一致。单据和分项提交共用归期、容量、快照与预算校验。

包肖通过 BetInput.package_zodiacs 表达每肖包号意图，普通请求省略空字段以保留已提交请求的幂等哈希。迁移 0010 为投注增加可空 JSON 字段，已有记录视为普通投注。展开和分配使用本期映射，在原子基础注中固定号码、整数分本金及赔率反水；金额调整和飞出按原包号重分配，逐号检查已有飞出上限。风险计算、统计和结算直接使用这些基础注。

PDF／PNG 在浏览器按同一快照、同一套排版指令生成，组合单按有效分项使用整数分汇总，并与服务端总额核对。水钱拆分取基础注快照比例和已舍入的结算结果；基础注、投注单、服务端汇总三层金额均需一致，和局基数单独排除。五列表格与最后合计共用同一组汇总值。PDF 绘制矢量文字；PNG 使用本地中文 FontFace 和逐页 Canvas，完成或取消后释放字体和画布。字体及库按需加载，VPS 不运行排版进程。退出、切期和取消终止下载，所有文件生成成功后才创建 ZIP。

## 归期与结算事务

business_date 将北京时间减去 6 小时后取日期，统一用于当前期、默认查询、映射生效校验、授权和历史清理。accepting_entries 仅表示收到请求时仍属于该业务期，与 phase／state 的开奖、结算状态分开。排队请求沿用进入中间件时捕获的服务器时间。

新增和金额变更先锁期次，再保存快照；已有有效开奖时通过共享 settle_recorded 在同一事务内结算待处理分项与飞出。后台首次结算和补录重算使用同一实现；撤销保留原判定并从有效账目排除。期次锁与统计快照锁保证不会读取混合版本。没有开奖时只排队更新风险，有开奖时风险缓存标为过期，预览直接使用真实结果。原时间表仅作为已有数据库数据保留，运行逻辑不读取它。

拖意图保存为可空 JSON：left、right、zodiac；迁移 0011 只增加该列。domain 统一校验候选池、拆注数量和容量，按本期映射展开，生成与普通投注相同的 Atom。金额纠正、飞出、风险和结算继续使用基础注快照，不重新按当前配置拆注。旧记录 drag 为空，不改写历史。

## 文本录注与确认式学习

TextEntry 在当前账号浏览器内存中把一份原文解析为一张组合单草稿；未知片段或歧义阻止整单预览，不会按行拆单。后端 text_entry 复用 domain 规划器只读预览，提交复用 betting 的整单事务、幂等与结算流程。客户确认的简称、玩法版本及金额方式与投注在同一事务内保存到客户库的 text_entry_preferences 表（迁移 0012），账号之间不共享。合成样本仅生成候选排序，不自动绑定玩法或学习真实金额。交互、接口和限制见[文本录注](../guides/text-entry-proposal.md)。

## 数据升级

迁移定义集中于 store::MIGRATOR。auth 执行迁移，受限 MarkSix 只读核对全部迁移版本、成功标记和校验值，拒绝与当前构建不一致的数据库；不再使用固定“版本至少为 7”的旧启动条件。

已发布迁移校验值不修改。规则与基础注缺省字段用于读取现有快照，属于数据契约，不能因取消旧交付方式而删除。风险结果属于派生缓存，可通过迁移失效并重新计算。应用回退只允许数据库迁移契约完全一致；详细恢复边界见 VPS 指南。

## 客户功能与录注偏好

`features.rs` 管理客户库中的功能开关及最近录注方式，通过 bootstrap 和设置接口提供同一份状态。录注与飞出写入在业务事务内读取开关，已提交请求重放仍返回原结果。关闭功能影响可用操作及界面展示，保留历史账目；统计计算与投注快照继续沿用原规则。

`text_entry.rs` 管理通用简称和按投注人关联的特码费率。费率关联只绑定本单使用的有效玩法，和投注保存原子提交；查询时读取玩法当前版本，停用或类型变更后不复用。前端异步匹配与报价分别取消过期请求，匹配完成后才允许确认。实际字段及接口见[文本录注](../guides/text-entry-proposal.md)。
