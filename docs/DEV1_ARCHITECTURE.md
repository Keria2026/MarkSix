# Dev1.0 托管版设计与实施记录

状态：已完成首次上线，后续变更通过 dev 验证并合并 master 后发布。实际验证范围见 [验收记录](DEV1_ACCEPTANCE.md)。旧部署和备份独立保留；托管版全新建库。

## 已确认的产品边界

- `https://3801.win`：客户工作台；`https://admin.3801.win`：运营管理后台。
- Nginx 负责 HTTPS 和反向代理，数据库和应用端口不直接对公网开放。
- 客户之间的账号、投注、玩法、配置、统计和账本完全隔离。
- 客户免安装；授权绑定账号，允许更换浏览器或设备；新登录使旧会话失效。
- 首次激活及到期续期均由运营方签发新的一次性激活码。码绑定账号和凭据版本。
- 授权截止日采用北京时间，当天当期仍可在封盘前投注。之后禁止新增业务，但完成之前已接受投注的抓取和结算。
- 提前续期从原截止日累加；过期后续期从当前业务日期计算。
- 修改密码保留剩余授权，注销全部旧会话并作废未使用旧码。
- 永久授权客户免到期限制，仍遵守金额、封盘、玩法、容量等业务规则，仍可被停用。
- 删除客户执行永久删除资料和账本，不采用归档。删除须明确确认，并处理相关备份，避免普通恢复重建已删除客户。
- Codex 推送 dev；运营方验收并合并 master；验证通过后自动部署 VPS。
- 首个 VPS：2 vCPU、1 GB 内存、40 GB 存储；目标最多 200 人在线。该目标必须压测验收，不等于允许 200 个同时执行的精确极值任务。

## 运维接入状态

首次 master 流水线已完成 VPS 自动部署及双域名公共健康检查。后续每次发布仍需验证构建、备份、迁移、服务健康和 TLS 路由，不能把上次验收当作本次结果。

## 验收边界

必须验证跨客户访问拒绝、单会话、并发核销、到期业务边界、旧投注延迟结算、删除期间的任务与连接清理、备份恢复与删除记录，以及更新失败后的恢复。所有容量和上线状态仅以实际测试记录为准。

## 数据与资源实现

客户业务库和数据库用户独立。统一客户服务从已验证会话选择账本，控制库连接只有所需表和列的权限。授权端管理客户和核销记录；已删除旧设备签名实现与 Windows／本机交付路径。历史迁移保留校验，新迁移清理已退役授权表。

热账本缓存最多 12 个，每池最多 2 个连接；8 个业务并发槽，计算中的账本保留上下文。提交时间在进入资源队列之前捕获，内层业务处理不覆盖。冷账本释放连接后按需重新打开，不影响数据。精确计算共享单个并发槽；成功与失败的开奖抓取结果共享短时缓存，避免外部接口异常时每个客户重复请求。

客户历史清空由授权端持有备份文件锁执行，客户服务仅转发已认证请求，不挂载备份。清空当前账号本期之前的数据，备份清空凭据随共享数据保留，恢复工具拒绝历史清空前的备份代次。
