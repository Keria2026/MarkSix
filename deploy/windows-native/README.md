# MarkSix Windows 原生版（无需 Docker / WSL / Node / Rust）

适用于 Windows 10/11 x64。程序在本机运行，浏览器访问 http://127.0.0.1:8088。
包含原生 marksix.exe、前端页面和 MySQL 8.4；仅监听本机，不对局域网开放。

## 首次使用

1. 完整解压 ZIP 到固定目录，例如 `C:\MarkSix`，不要在压缩包中运行。
2. 首次使用建议运行包内微软签名的 `vc_redist.x64.exe` 安装 VC++ x64 运行库（MySQL 所需；可能提示管理员授权）。已安装对应运行库可以跳过。
3. 双击 `Install.cmd`，设置并再次确认管理员密码（至少 12 个字符）。默认账号 `admin`。
4. 等待数据库初始化和页面自动打开，登录后填写你自配的授权服务 HTTPS 地址和一次性授权码。首次使用／到期续期均需授权；正常使用每 60 秒联网核验。详情见包内 LICENSING.md。之后双击 `Start.cmd` 即可使用。

命令行自动化可设置 `MARKSIX_NO_PAUSE=1` 关闭包装器暂停；失败会保留非零退出码。

所有安装、启动、停止操作使用同一个 Windows 用户。无需管理员权限运行 MarkSix。
安装包包含依赖，运行库安装完成后可离线初始化数据库；激活、授权核验和自动获取开奖结果需要网络。
不安装 Windows 服务、不设置开机启动。重启电脑后需要重新运行 Start.cmd。
运行期间请保持该用户登录。

## 停止、备份与更新

- `Stop.cmd`：先请求应用优雅退出，再用认证 shutdown 关闭 MySQL，确认 8088／33306 已关闭；可重复执行。失效 PID 不会误杀其他程序，无法验证占用进程时会明确报错。请在移动安装目录或关机前执行。
- `Backup.cmd`：运行中生成完整 MySQL SQL 备份，位于 `%LOCALAPPDATA%\MarkSix\backups`。备份包含业务数据及账号哈希，请妥善保管，并复制到其他磁盘。
- 更新：先用旧包 Backup.cmd，再 Stop.cmd，保留备份和旧程序包，再解压新包并运行 Install.cmd。已有账号和数据库会保留。数据库迁移可能不支持旧版程序；回退前应恢复对应备份。
- 数据目录：`%LOCALAPPDATA%\MarkSix`，独立于程序目录。删除或覆盖此目录会丢失数据。
- config.json 中的凭据由 Windows DPAPI 加密，只能由原 Windows 用户解密。不要仅复制该文件到另一台电脑。跨机器迁移使用 SQL 备份，在目标机先初始化本版，再执行 Restore.cmd。新设备需要重新激活。
- 恢复／迁移：命令行执行 `Restore.cmd "C:\备份目录\backup.sql"`，也接受 Ubuntu 生成的 `.sql.gz`。恢复前须启动数据库，输入 RESTORE 确认覆盖；脚本自动生成恢复前备份，导入成功后迁移并重启，失败时保留停止状态。只恢复受信任的完整 marksix SQL 备份。旧部署的数据不会自动迁入。

## 中文用户名和中文路径

v0.3 保留 `%LOCALAPPDATA%\MarkSix` 原始数据位置，为 MySQL 自动创建纯 ASCII 路径入口：`%ProgramData%\MarkSix\<当前用户 SID>\<路径标识>\data` 和 `runtime`。它们是 NTFS 目录联接，指向原数据和程序依赖，不是新的数据库副本。

MySQL 的配置、初始化脚本、日志和备份参数均使用该入口；PowerShell 配置读取显式采用 UTF-8。支持中文 Windows 用户名、中文安装路径及带空格路径，无需重命名 Windows 用户。

请使用本地 NTFS 磁盘，并确保当前用户可在 ProgramData 创建自己的目录。不要手工修改或递归删除联接入口；删除目标数据仍会丢失数据。已失败的旧初始化不会自动删除重建：先保留数据及日志，确认没有业务数据后再由维护人员恢复。

升级时先运行旧包 Backup.cmd，再 Stop.cmd；完整解压新包并用原 Windows 用户运行 Install.cmd。新包不会修改原账号密码，历史规则快照保持不变。

## 故障排查

- 8088 为网页端口，33306 为数据库端口；被占用时会停止并报错，不会结束其他程序。请先关闭占用程序（包括原 Docker 部署）。
- 窗口提示缺少 DLL / MySQL 无法启动：安装包内 vc_redist.x64.exe 后重试，必要时重启 Windows。
- 数据目录内的 `mysql-error.log`、`app.stdout.log`、`app.stderr.log` 可用于诊断。
- 首次初始化中断且已有部分数据库文件：程序会保留现场并拒绝覆盖，请先检查日志，不要盲目删除数据。
- 不要同时启动不同目录的两个版本。
- manifest.json 记录构建提交、MySQL 下载来源和文件 SHA256；启动前检查文件完整性。

MySQL 的版权、许可证及附带文档保留在 mysql 目录；VC++ 运行库采用微软自带安装条款。
